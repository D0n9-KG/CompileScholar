# 科研场景下复杂学术查询的智能论文搜索与推荐 —— 技术报告

**项目名称**：LogicKG：自演化知识超图驱动的学术论文智能搜索系统

## 摘要

本系统面向科研场景下的复杂学术查询，构建了"多层检索漏斗 + 自演化知识超图"的端到端论文
搜索与推荐系统。系统覆盖查询理解与分解、多源多策略检索、语义-权威融合排序、以及结构化
归纳展示的全流程。区别于现有系统（PaSa/SPAR/Ai2 Paper Finder）在纯相关性排序上的设计，
我们将**自演化知识超图**引入检索流程的多个环节：引用意图边（extends/improves/compares）
支持选择性引文导航，跨论文概念合并的变体词典辅助查询扩展，方法演化链支撑结果的归纳整理
与可溯源输出。

在 SPARBench 练习集上，我们通过系统性的诊断-修复迭代将 set-F1 从 0.007 提升至
【R_final：全量三臂数据待填】，并通过逐层损耗分解（召回覆盖 49%→判分窗口→判分精度→
输出容量）定位了每一层的改进空间。系统单查询成本 $0.001-0.003、端到端延迟 13-30 秒
（快模式），全链路构建于本地 sci-evo 全文获取/解析服务之上，检索后端对接 Semantic
Scholar / OpenAlex / Crossref 三家学术搜索 API。

## 1. 问题理解与总体架构

### 1.1 赛题分析

赛题要求构建端到端学术论文搜索系统，覆盖查询理解→多策略检索→综合排序→归纳整理四环。
评测中 F1 占 70%（公开+隐藏测试集自动评分）、效率 20%、结构化 10%，专家评分 40%
（创新 15%/落地 15%/泛化 10%）。

我们对赛题的关键判断：

1. **复杂学术查询的核心矛盾是"专家式语义"与"检索式语义"的鸿沟**。以练习集 SPARBench
   为例，标准答案（gold）是专家人工筛选的代表性论文清单，其中大量论文（预印本、缩写
   标题、跨子领域经典）与查询字面相似度极低——纯关键词检索结构性够不着。
2. **单轮检索存在原理性天花板**。我们实测：单一检索源在 gold 覆盖率上的上限约为 50%
   （详见 §3.1），赛题要求的"多轮检索、引文网络探索、跨文献关联推理"正是突破该天花板
   的手段——这也正是知识超图的用武之地。
3. **效率是硬指标**。成本控制（API 调用、Token 消耗）计入评分，要求系统在检索源预算、
   LLM 调用次数上有显式的设计取舍，全流程成本可度量。

### 1.2 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│  L0 查询理解：意图解析 → 子查询分解 → 查询改写扩展              │
│     （超图位①：概念变体词典辅助查询扩展）                       │
├──────────────────────────────────────────────────────────────┤
│  L1 多源召回：S2 bulk 语义召回 + Crossref（权威信号）          │
│     + OpenAlex 引文滚雪球（预算纪律内）                        │
│     候选池 ~2000-4000 篇/查询 → embedding 语义重排选窗          │
├──────────────────────────────────────────────────────────────┤
│  L2 综合排序：分块 LLM 判分（标题+摘要+被引）→ H/S/N 分档      │
│     → 语义-权威混合排序（超图位②：结构化关联推理加分）           │
├──────────────────────────────────────────────────────────────┤
│  L3 归纳整理：按查询意图组织输出——方法演化链（A improves B）    │
│     方法族分组 / 每条结果带可溯源 evidence（超图位③）           │
└──────────────────────────────────────────────────────────────┘
        ▲ 持久化知识超图（graph_store）：检索循环中增量生长
          PAPER 节点 + 引用意图边 + 概念节点 + 自演化 schema
```

三个可插拔的超图参与位（检索前/L1.5/L3）+ 一张持久化、增量生长的知识超图，是本系统
区别于三个参考系统的架构特征。

## 2. 核心技术方案

### 2.1 查询理解与分解（L0）

自然语言查询进入后，LLM 完成三类解析：核心研究意图、多维度约束（主题/方法/时间/venue）、
子查询分解。改写策略生成三类查询变体：宽泛核心词（2-3 token）、综述型变体（"XX
survey"，实测显著提升代表性 gold 召回）、具体面向变体（技术+任务组合）。

**超图位①——概念变体词典**：知识超图在增量建图过程中通过跨论文概念合并积累"同一概念
的多种叫法"（如 DQN/Deep Q-Network/value-based (DQN) 归一到一个节点）。查询中的领域
术语命中图上概念时，用图上学到的变体扩展检索词表——这是"图参与检索"而非"图参与排序"
的更前置形态。机制验证：领域重叠时扩展词显著不同质（携带 SlateQ、Dyna-Q 等图词汇）；
当前限制（域重叠门控、扩展词到 gold 召回的转化）在 §5.2 诚实讨论。

### 2.2 多源召回与语义重排（L1）

**召回源组合**（三家学术 API + 引文扩展）：

| 检索源 | 角色 | 关键实测 |
|---|---|---|
| Semantic Scholar（bulk 端点） | arXiv 覆盖主力 | 收录但排序缺失是主要损耗源 |
| Crossref | 权威信号（被引数） | 不收录 arXiv-only 论文（gold 覆盖仅 3.9%） |
| OpenAlex | 引文滚雪球 + 元数据 | 一跳后向扩展实测 +1 gold（DRN 案例） |

**Embedding 语义重排层**：S2 bulk 返回无相关性排序（实测：被引 30k 的经典论文在匹配集
内但被随机采样排除在返回页之外）。我们在召回与判分之间插入语义重排——用 embedding 模型
计算"查询 vs 候选标题+摘要"的 cosine 相似度，对 2000-4000 篇候选池做全量重排，选窗进入
LLM 判分。注入实验验证：5 篇目标 gold 混入 85 篇混合候选池后，3 篇浮入语义重排 top-10。

### 2.3 分块判分与混合排序（L2）

**分块判分**：LLM 对候选做 H（高度相关）/S（部分相关）/N（不相关）三档判分，输入为
标题+摘要摘录+被引数。两个关键工程设计均有消融实证：
- **分块（50 篇/块）**：150 篇整列判分存在注意力稀释（实测窗口内 3 篇 gold 全部漏判，
  分块后 3/3 命中）
- **摘要辅助判分**：纯标题判分对泛化标题（"Research on..."式）的 niche 论文系统性盲视
  （实测 7/12 在池 gold 判分为 N），摘要摘录进入判分输入后该盲区显著缓解

**混合排序**：H 档内部按"语义相似度 60% + 被引权威 40%"混合分排序。三臂消融实验
（纯语义/混合/纯被引，50 查询全量）显示【R_final：三臂数据待填】——纯语义排序对
具体技术型查询增益显著（climate 查询 F1 +200%），纯被引排序对综述代表性查询有不可
替代的分辨力，混合策略兼顾两者。

### 2.4 知识超图的构建与三个参与位

**超图本体**：节点分概念层（METHOD/PHENOMENON/PARAMETER 等类型，跨论文合并）与论文层
（PAPER 节点）；边含概念间的 schema 模式边（extends/improves/compares 等 29 种自演化
pattern）与论文间的引用意图边（cites，带 extends/improves/compares/replaces/adapts/
background 六类意图标注）。所有边携带 verbatim evidence 与事务日志（ledger），可溯源、
可重放。

**引用意图抽取**（已并入主管线）：对论文全文定位引用提及（编号式+作者-年份式双格式正则），
LLM 判定引用意图，产出论文间 cites 边。语料内引用图验收：16 条边与独立旁路实现完全对齐
（边对 16/16，意图一致 15/16）。

**自演化 schema**：抽取模式库（T-box）随语料增量演化——离线演化出的 29-pattern ML 域
schema 相比 12-pattern 种子 schema，在相同语料相同判分下召回 +24%（808→1001 边）、跨
域迁移成立（granular 域无衰退）。这是"离线演化 + 在线 frozen"架构的承重证据。

**持久化与增量生长**（graph_store）：知识图以命名图形式持久存储（原子写、断点续跑、
跨批次引文网络生长），检索循环中每轮增量建图 3-5 篇，图随使用规模自然增长——图是系统的
持久资产而非每次查询的临时产物。

**超图位②——结构化关联推理加分**（L2）：【E 实验数据待填——图直连信号（引用邻居直入池/
概念共现直传）vs 纯语义基线的对照结果】

**超图位③——可溯源归纳输出**（L3）：按查询意图组织结果——"找 X 的改进"类查询沿
improves 边给出方法演化链（每条边带论文级 evidence 原文），综述类查询按方法族分组。
全部输出可回溯到超图边→evidence span→论文元数据的完整链条。

## 3. 实验与结果

### 3.1 系统性诊断：召回覆盖的分层实测

我们在 SPARBench 前 10 查询（129 篇 gold）上对召回覆盖做了逐层实测：

| 层 | 实测数据 | 含义 |
|---|---|---|
| Crossref 池 | gold 覆盖 5/129（3.9%） | 大量 gold 为 arXiv-only，Crossref 结构性不收录 |
| S2 bulk 池 | 63/129（49%） | 主力源；但返回无排序（见 §2.2） |
| 引文一跳扩展 | +1（DRN） | 缩写标题论文靠引文链捞回的唯一实例 |
| LKM（玻尔） | 并集 +1 | 与 S2 高度重叠，作为辅助源 |

结论：单轮检索的 gold 覆盖天花板约 50%，剩余 51% 是"收录但未召回"（排序/采样问题）与
"跨子领域专家清单"（需多轮/关联推理）的混合。该分解直接指导了语义重排层（§2.2）与
检索循环（§5.1）的设计。

### 3.2 诊断-修复迭代链（F1 改进主链）

| 轮次 | 修复内容 | micro-F1 |
|---|---|---|
| R1 | 基线：Crossref 召回+LLM 过滤 | 0.007 |
| R3 | +S2 bulk 多改写（含 survey 变体） | 0.014 |
| R7 | +判分窗口修复+分块判分（确定性管线） | 0.093 |
| R8 | +embedding 重排层+摘要辅助判分 | 0.086* |
| R9 | +纯语义输出排序 | 0.072* |
| R10 | +自适应输出容量 | 0.029* |
| 【R_final】 | 固定容量 20+混合排序（50 查询全量三臂） | 【待填】 |

*注：R8-R10 为 10 查询上的消融轮（单变量归因用），非单调改进；其中 R9 揭示了排序信号
的查询类型依赖性（语义排序使 climate 查询 +200% 但综述查询 -67%），R10 揭示了判分档位
规模不可直接用作输出容量信号。这两个发现直接构成最终排序设计的依据。

【R_final 表：50 查询 × 3 排序臂 × micro/macro-F1/P/R，待全量数据】

## 4. 工程实现与落地性

1. **全链自持**：本地 sci-evo 服务提供论文获取（arXiv DOI→PDF）→MinerU 全文解析→
   结构化 content_list 的完整链路，检索/建图/解析不依赖人工干预。
2. **一键入口**：`python -m contest.run "查询"` 即可运行全流程并输出成本报告。
3. **持久化图存储**：命名图+原子写+断点续跑（崩溃最多损失单篇在建论文）。
4. **效率优化链**（均有实测）：引用意图分类并发化（~4×）、verify 批次 schema 瘦身
   （-60% 输入 token）+ 批间并发、分块判分注意力修复。
5. **模型与成本声明**：抽取/判分使用 DeepSeek-V4-Flash（关 thinking），embedding 使用
   qwen3-embedding:8b（CST），判分独立性与成本已按调用打点。

## 5. 诚实边界与讨论

### 5.1 多轮检索循环：设计与实测边界

我们实现了完整的图驱动多轮循环（检索→选种→增量建图→图信号扩展→再判分），并在单查询
闭环实验中做了严格的双臂对照（图驱动查询 vs 摘要改写查询）。结果：图词汇确实传导进了
查询（携带图上学到的算法名词汇），但目标 gold 召回 0/5 vs 对照 1/5——诊断出两层根因：
召回端的无排序采样（工程问题，已由语义重排层缓解）与**图信号经 LLM 中间层的稀释**
（更本质：图→LLM 生成查询→检索的链条中，LLM 参数先验压过图信号）。后续的直连路径
设计（引用邻居直接入池、概念共现直传论文身份，绕开 LLM 中间层）是解决该问题的方向，
【E 实验判决待填】。

### 5.2 已知限制

1. 概念变体查询扩展受域重叠门控（图未覆盖查询域时零增益）——冷启动依赖增量建图。
2. SPARBench 练习集的 gold 存在数据瑕疵（citationCount 字段 55% 缺失、个别查询 gold
   含重复项），我们的全部数字在该口径下测得并在报告中如实标注。
3. S2 API key 申请未获批期间，使用 bulk 端点替代语义检索端点（排序能力受限，见 §2.2
   的语义重排补偿设计）。

## 6. 与参考系统的对比定位

| 维度 | PaSa | SPAR | Ai2 Paper Finder | 本系统 |
|---|---|---|---|---|
| 检索源 | Google site:arxiv | 五源路由 | S2 全家桶 | S2+Crossref+OpenAlex |
| 排序信号 | RL 训练的 Selector | 相关分+权威+时间 | 相关分+MAB 预算分配 | 语义+权威混合+【图结构】 |
| 引文利用 | Crawler 深度遍历 | RefChain 一层扩展 | 引文追踪 | **引用意图标注的选择性导航** |
| 输出形态 | 论文列表 | 论文列表 | 论文列表 | 列表+演化链+方法族+evidence 溯源 |
| 知识资产 | 无（会话式） | 无 | 无 | **持久化自演化知识超图** |

差异化声明：三个参考系统的排序全部是"相关性+权威+时间"的启发式组合，无一引入跨论文的
**结构化关联推理**；引文利用上 PaSa 用 RL 学习"深入哪篇"，我们用引用意图边（结构先验）
回答同一问题。我们的图是持久资产且随使用增长——检索行为的副产品沉淀为系统能力。

## 7. 泛化性设计（专家评分 10%）

1. 抽取栈域无关验证：4 域（ML/生物/流体/分子动力学）实测零 granular 泄漏（GRANULAR
   LEAKAGE=0）；ML 域演化 schema 迁移至 granular 域无衰退。
2. 查询域自适应：增量建图管线对任意域论文即插即用（成本 §3.4），域覆盖随使用自然扩张。
3. 评测域分布对冲：SPARBench 含 30% 生物查询，快模式（纯检索）对域不敏感；深模式的
   建图能力已验证跨域（DRL 域 6 篇+LLM 域 50 篇在建）。
