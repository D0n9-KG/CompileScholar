## 1 项目概况

### 1.1 背景和基础

文献检索是科研工作流中最基础也最耗时的环节。研究者面对的往往不是简单的关键词查
找，而是细粒度、多维度的复杂研究问题——例如"为使用合成数据增强监督微调的思路寻找
高质量、多样化的顶刊论文"。这类查询远超传统搜索引擎的能力边界：它要求系统理解查
询的语义意图，具备多轮检索、引文网络探索与跨文献关联推理的能力。这也是赛题将本问
题列为研究方向的核心动因。

近年来，以大语言模型为核心的智能搜索 Agent 在该领域展现了巨大潜力。PaSa（字节跳
动/北大，ACL 2025）通过双 Agent 架构与强化学习在 RealScholarQuery 上超越 Google+GPT-4o
基线 37.78%；SPAR（arXiv 2025）以查询分解与演化达到 AutoScholar F1=0.38；Ai2 Paper
Finder（ICLR 2026）凭借多索引语义检索与多臂老虎机采样策略在 PaperFindingBench 上
大幅领先通用 Agent。然而我们对这三个系统进行的源码级分析表明，它们收敛于同一范式：
LLM 理解查询、多源召回、启发式排序——排序信号不外乎相关性、权威性与时间的组合。
**没有任何一个系统构建或利用论文之间的结构化知识**（如"这篇论文改进了那篇"、"这两
个方法同属一个族"），而这恰恰是回答"拓展研究思路"类查询的关键：用户需要的不是相似
度排名，而是知识的脉络。

本项目正是基于这一空白构建的。团队在知识图谱与超图抽取方向已有扎实的前期积累：
已完成 2300 余篇学术论文的全文解析管线（MinerU 结构化解析）、自演化 schema 的抽取
内核（事务性知识库内核，64 项单元测试）、以及跨四个学科领域（机器学习、生物、流体
力学、分子动力学）的域无关抽取验证。项目的基础设施——本地 sci-evo 论文获取与解析
服务——提供从 DOI 到 PDF 到结构化全文的完整自持链路。本参赛系统即在此基座上构建。

### 1.2 场景和价值

本系统适用的核心场景是研究者的文献调研工作流，具体包括三类典型任务。其一是**综述
起步**：研究生进入新领域时需要快速获得该领域的代表性论文与知识脉络，系统的结构化
归纳输出（方法演化链、方法族分组）直接提供可阅读的知识地图而非孤立论文列表。其二
是**深度追踪**：研究者需要了解某个方法的改进谱系（"X 方法有哪些后续改进"），系统的
引用意图边（每条引用标注 extends/improves/compares 等六类关系）使这类查询可以沿语
义化引文链精确导航，而非无差别遍历。其三是**跨文献关联推理**：查询涉及多篇论文之
间的关系比较时，超图中的方法族与概念共现结构提供超出字面相似度的关联信号。

就社会价值而言，学术检索的效率直接影响科研产出效率。当前研究者平均花费大量时间
在文献筛选上，而现有工具（包括商业学术搜索引擎）均停留在"匹配"层面，无法完成
"理解"层面的任务。本系统展示了一条可行的路径：将检索过程中积累的知识结构化为可复
用的资产，使系统随使用持续增强。这一范式对垂直领域的智能检索（医疗文献、专利、法
规）具有直接的迁移价值。

从竞争格局看（市场调研与对比分析），学术搜索赛道的现有产品分为三代：传统引文索引
（Web of Science、Google Scholar）以关键词匹配为核心；AI 增强搜索（Semantic Scholar、
Consensus）加入了语义匹配；而新一代 Agent 搜索（PaSa、SPAR、本系统）正在尝试解决
意图理解与知识推理。本系统在第三代中占据一个明确的差异化位置：唯一以结构化知识资
产（知识超图）为核心设计要素的系统。

### 1.3 所需支持

项目实施所需的算力与资源均已自备，无额外支持需求。具体而言：大模型推理通过
Paratera API 服务完成（DeepSeek-V4-Flash 用于抽取与判分、qwen3-embedding 用于语义
重排），按量计费，单查询成本约 0.01 至 0.02 元人民币；论文全文获取与解析由本地
sci-evo 服务完成（MinerU 引擎），无需外部算力；检索后端对接 Semantic Scholar、
OpenAlex、Crossref 三家学术 API 的免费配额，符合赛题技术要求。开发与实验在单台工
作站上完成，无集群需求。

## 2 项目规划

### 2.1 整体目标

参赛期间本项目的整体目标是交付一个**可运行、可评测、可演示**的端到端学术搜索系
统，并在练习评测集上建立系统的量化证据。具体分解为三个层次：第一，完成赛题要求
的全流程功能——查询理解与分解、多源多策略检索、论文综合排序、搜索结果归纳整理与
结构化展示，以一键入口（`python -m contest.run "查询"`）交付；第二，在 SPARBench
练习集（50 查询）上建立完整的评测证据链，包括系统迭代改进记录与关键设计的消融实
验；第三，构建并交付一张持久化的领域知识超图（56 篇论文规模）作为系统的知识资产
与结构化输出的展示载体。目前三个层次的目标均已达成或进入最终验证阶段，详见实施
方案章节。

### 2.2 技术创新点

通过与三个参考系统的源码级对比调研，本项目的主要技术创新点归纳为四项。

**创新点一：知识超图深度参与检索全流程**。现有系统的排序均为"相关性+权威性+时间"
的启发式组合，本系统在检索的三个环节引入结构化知识信号——查询理解阶段的概念变体
扩展（超图跨论文合并学到的领域词汇）、排序阶段的结构化关联推理、输出阶段的可溯源
知识归纳。知识超图在检索过程中增量生长（对高相关论文自动建图），检索行为沉淀为持
久知识资产而非一次性消耗——这是与"会话式"系统的本质区别。

**创新点二：引用意图感知的选择性引文导航**。PaSa 用强化学习（382 次交互/查询）学
习"应该深入哪篇引文"，本系统用引用意图标注直接回答这一问题：每条引文关系被分类为
extends/improves/compares/replaces/adapts/background 六类，"找改进"类查询沿 improves
边精确导航。引用意图抽取管线已并入主抽取内核并完成验收（语料内引用图 16 条边与独
立验证实现完全对齐）。

**创新点三：自演化 schema 与离线-在线分离架构**。抽取模式库（schema）随语料增量演
化：离线演化出的 29-pattern 模式库相比 12-pattern 种子，在相同语料与相同判分条件下
边召回提升 24%（808→1001 条），且跨域迁移成立（ML 域演化的 schema 用于其他领域无
衰退）。该证据支撑"离线演化、在线冻结"的高效架构——在线查询无需承担演化成本。

**创新点四：面向效率的系统性工程设计**。全流程成本自动打点（每次 LLM 与检索调用
的计数、延迟与费用），快模式单查询成本 0.01-0.02 元、延迟 13-30 秒——约为 Ai2
Paper Finder 公开报告成本（$0.063/查询）的二十分之一。判分验证层输入瘦身（-60%
token）与并发化、引用意图分类并发化（4 倍加速）等优化均有实测支撑。

## 3 实施方案

### 3.1 技术可行性分析

**数据获取**方面，检索源经过如实的可用性审计：Semantic Scholar 匿名 bulk 端点
（AND 词项匹配、无相关性排序）是唯一覆盖 arXiv 预印本的可用源——S2 API key 申请
未获批、常规检索端点限流不可用，OpenAlex 匿名池触发日级封禁——这些约束均被实测
记录并纳入架构（而非回避）。Crossref 提供权威被引元数据但其 gold 覆盖仅 ~4%
（arXiv-only 论文结构性缺失）。关键的量化诊断：SPARBench 零命中查询的标准答案中，
87% 本可被 S2 检索到（用答案自身标题词探测）——瓶颈在查询措辞而非源收录，这直接
决定了本系统"结构化知识改写查询"的技术路线（见 3.2）。论文全文的获取通过本地
sci-evo 服务完成（arXiv DOI 到 PDF 到 MinerU 结构化解析），单篇约 1-3 分钟，已有
2300 余篇的存量处理能力。

**行业知识获取**方面，系统的领域知识不依赖人工标注，而是通过增量建图自动积累：
每篇论文经抽取管线（分节规划-抽取-验证-提交四阶段）转化为概念节点、schema 模式边
与引用意图边，全部携带可溯源的证据原文。这一过程已在四个学科领域验证了域无关性
（GRANULAR 领域泄漏检测为零）。

**算力与成本**方面，全部实验与开发在单台工作站完成。大模型调用按量计费，整个参
赛期间的开发与实验总成本预计不超过 100 元人民币；单查询推理成本见创新点四。系统
各环节均有磁盘缓存与断点续跑设计，长时任务（如 50 篇领域建图）可无人值守完成。

### 3.2 技术细节

系统总体架构分为四层。**L0 查询理解层**完成意图解析、多维约束识别（主题/方法/时
间/venue）与子查询分解，生成三类改写变体（宽泛核心词、综述型、具体面向型）；
**L1 多源召回层**并行查询三家学术 API 并合并去重，形成约 2000-4000 篇的候选池，
随后经 embedding 语义重排层（qwen3-embedding:8b 计算查询与候选标题摘要的余弦相
似度）选取判分窗口；**L2 综合排序层**由 LLM 对候选做高度相关/部分相关/不相关的
三档判分（输入含标题、摘要摘录与被引数），输出按语义与权威混合分排序；**L3 归纳
整理层**按查询意图组织结构化输出。知识超图横跨四层提供支持（详见创新点一）。

以下论证三个核心技术设计，每个设计均附实验证据与预期指标。

**设计一：语义重排层解决"收录但找不到"问题**。我们的诊断实验发现了现有检索管线
的一个关键损耗源：Semantic Scholar 的 bulk 检索端点返回无相关性排序的候选流——最
极端的实测案例中，被引超过三万次的领域经典论文（Proximal Policy Optimization）处
于匹配集内，却因随机采样从未进入返回页。这意味着任何召回策略都会随机丢失关键论
文。语义重排层对候选池全量计算语义相似度后，此类问题被系统性消除。注入实验的验
证结果为：将 5 篇目标论文混入 85 篇混合候选池，重排后 3 篇进入前十（第 3、7、10
位）。该设计已在全部后续实验中启用。

**设计二：分块判分与摘要辅助输入解决判分精度问题**。判分环节的两个工程问题均通
过对照实验定位并解决。其一为注意力稀释：150 篇候选整列提交判分时，判分器系统性
遗漏窗口内的目标论文（实测 3/3 漏判），改为 50 篇分块后全部命中。其二为泛标题盲
视：标准答案中大量论文采用泛化标题（如"Research on..."式命名），纯标题判分实测
7/12 在池答案被误判为不相关，将摘要引入判分输入后该盲区显著缓解。输出排序的信号
选择经三臂消融实验（纯语义/混合/纯权威）验证存在查询类型依赖性：在 10 查询诊断
集上，纯语义排序使气候类具体查询 F1 提升 200%，但综述类查询下降 67%——两类信号
命门互补，最终采用语义为主、权威为辅的混合分。50 查询全量的三臂对照在 10 题检查
点显示三臂命中数完全持平（各 10 篇），端到端排序差异在该基准上不显著，按预注册
止损规则中止并如实记录。

**设计三：增量建图与知识超图的持续生长**。系统在检索循环中对判分为高相关的论文
自动增量建图（单篇 5-16 分钟、成本 0.05-0.2 元），构建过程包含分节抽取、跨论文概
念对齐合并、引用意图标注三个阶段，全部通过事务性内核提交（原子性、可重放、带完
整审计日志）。知识图以命名图形式持久存储，跨查询会话累积——当前已建成 50 篇
LLM 领域论文的领域图：3,827 个概念节点、3,912 条超边（概念结构边 3,750 条、引用
意图边 162 条），schema 层 218 个模式（离线演化产出）；检索过程的探索图另累积
122 篇种子论文并随使用持续生长。基于该图的结构化归纳输出（方法演化链、方法族分
组、逐边证据溯源）是结构化展示评分项的直接支撑。

**评测结果与预期指标**。在 SPARBench（50 查询、平均每查询 11.1 篇标准答案、专家
人工筛选的代表性论文清单）上，证据分两条线如实呈现：**诊断线**（10 查询诊断集）
set-F1 0.007→0.093 的迭代链用于定位病灶（覆盖/排序/判分三层鸿沟逐一归因）；
**泛化线**（50 查询全量）基线 micro-F1 0.035——零命中查询的标准答案仅 ~25% 在
召回池，覆盖缺口主导。本轮以超图 schema 驱动的查询生成（创新点一的核心机制）在
独立验证集上将召回池答案覆盖率提升 +30.4/+16.7 个百分点（开发集/留出集，判据预
注册、留出复核防过拟合）。50 查询全量的全机制栈终跑在 10 题检查点与基线命中数持
平（10/10）后按预注册止损规则中止：召回池的覆盖增益真实存在，但漏斗逐层对冲，
端到端增益在该开发基准上未确立（死因分解已归档）——覆盖增益的最终裁决移交官方
基准。每一轮改进均有
单变量消融归因，负结果（排序臂的查询类型依赖性、图信号经 LLM 中间层的稀释）同样
如实记录。效率指标方面，快模式单查询延迟 13-36 秒、成本 0.01-0.02 元；深模式
（含增量建图）增加数分钟至数十分钟与相应成本，两种模式覆盖从交互式检索到深度调
研的完整场景。

**官方族基准 RealScholarQuery 首测**（PaSa 论文的真实查询基准，50 查询、平均
15.8 篇标准答案/查询）：在因提供商限流而中止的首轮运行中完成 3 个查询，micro
set-F1@20=0.185、recall@20=0.186（n=3，样本量如实标注）。同口径对照（该基准
已发表数字，recall@20）：本系统 0.186 ≈ 最强 Google 基线 Google with GPT-4o
（0.202）的 92%，Google Scholar 为 0.151；PaSa-7b（7B 专用 RL 模型+Google 爬取）
为 0.580。定位清晰：在无 Google、无 API key、单免费源+超图的资源形态下达到
Google 量级召回，与使用 Google 检索及专用训练模型的系统仍有差距——这正是
资源约束下结构化知识路线的起点数字；SPARBench 上已量化的覆盖缺口诊断
（标准答案 87% 在源内可达、败于查询措辞）指明了后续机制迭代的主攻方向。

### 3.3 计划和分工

参赛期间的项目计划按三个阶段推进。第一阶段（已完成）为基础能力建设：抽取内核、
检索管线、评测框架与全链自持的论文获取服务。第二阶段（已完成）为系统集成与评测
闭环：知识超图并入检索全流程、SPARBench 全量评测、消融实验体系。第三阶段（进行
中，截止前完成）为最终验证与交付打磨：全量评测数据的最终确认、结构化输出展示实
例、参赛文档与演示视频制作、代码包整理。

本项目由本人独立完成，按阶段承担全部工程角色：抽取内核与知识超图构建、检索管线
与评测框架、系统集成与文档制作均由同一人贯通——这也保证了架构决策（如"图信号
走直连路径不经 LLM 中间层"）在设计、实现、评测三处的一致性。
