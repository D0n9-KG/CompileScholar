## Related Works

## LLM Serving Architectures and KV Cache Fundamentals

The Transformer architecture, which relies on a self-attention mechanism, enables efficient parallelization and the handling of long-range dependencies, serving as a foundational breakthrough for Large Language Models (LLMs) [1]. In cloud environments, serving these models requires balancing computational and memory demands, particularly during inference where high throughput and low latency are critical [2][3]. A primary bottleneck in LLM inference is the Key-Value (KV) cache, which stores intermediate representations to avoid redundant computations but scales linearly with sequence length and batch size, leading to significant memory consumption [4][5]. To address this, PagedAttention was introduced to manage KV cache memory efficiently by minimizing fragmentation and enabling flexible sharing, thereby improving throughput in systems like vLLM [6]. Further architectural optimizations include Multi-Query Attention (MQA) and Grouped-Query Attention (GQA), which reduce the size of key and value tensors by sharing them across attention heads, thus lowering memory bandwidth requirements for incremental decoding [7][8].

Beyond architectural changes, various system-level and algorithmic strategies have been developed to optimize KV cache management. Quantization techniques, such as KIVI, exploit the distinct element distributions of keys and values to apply asymmetric 2-bit quantization, reducing cache size without tuning [9]. Similarly, MiniKV employs a 2-bit layer-discriminative KV cache to achieve high compression ratios while maintaining accuracy for long-context tasks [10]. For long-context inference, ShadowKV stores low-rank key caches and offloads value caches to reduce memory footprint, while DiffKV introduces differentiated memory management that accounts for the varying importance of tokens and attention heads [4][11]. Other approaches include PQCache, which treats KV cache storage as an embedding retrieval problem using Product Quantization, and D2O, which dynamically optimizes KV cache size at both layer and token levels to preserve essential context [12][13].

Scheduling and eviction policies are also critical for efficient serving. LayerKV addresses Time to First Token (TTFT) delays caused by KV cache allocation conflicts through layer-wise block management and SLO-aware scheduling [14]. H2O proposes an eviction policy based on the observation that a small portion of "Heavy Hitter" tokens contributes most to attention scores, dynamically retaining these tokens to balance recent and important context [5]. In streaming applications, StreamingLLM leverages the "attention sink" phenomenon, where initial tokens receive strong attention scores, to enable stable inference over infinite sequence lengths without fine-tuning [15]. At the system level, frameworks like ScaleLLM optimize end-to-end efficiency by addressing bottlenecks beyond local inference, while QLM manages queues for mixed interactive and batch requests to improve SLO attainment and resource utilization [3][16]. Additionally, ConServe facilitates the co-serving of online and offline tasks by implementing fine-grained GPU harvesting and incremental KV cache management to handle load variability [17].

Caching strategies extend beyond the token level to include instruction-level caching. InstCache proposes a predictive caching mechanism that leverages LLM capabilities to reorder instruction representations, creating spatial locality to predict and cache potential instruction-response pairs [18]. However, the widespread use of cache-sharing methods to enhance efficiency by reusing cached states also introduces security risks, such as timing side-channel attacks that can leak private inputs [19]. While these techniques significantly improve inference efficiency, the specific workload patterns of KV reuse in real-world production environments remain an area requiring systematic characterization to inform optimal eviction policies [18][20].

## Workload Characterization and Trace Analysis

Understanding the behavior of Large Language Model (LLM) serving systems requires detailed analysis of workload patterns, yet obtaining real-world traces remains challenging [1]. Because real-world traces are difficult to acquire, synthetic trace generation has emerged as a promising alternative for understanding complex computer system behavior and managing resources [1]. Recent approaches, such as TraceLLM, utilize LLMs to generate synthetic microservice call graphs by training models to generate recursively, which captures complex hierarchical structures and implicit constraints [1]. This method applies instruction tuning to align generated traces with desired features, producing diverse and realistic traces that outperform existing approaches in accuracy and validity [1]. While synthetic traces can effectively replace real data for optimizing microservice management tasks, they may not fully capture the specific nuances of LLM inference workloads [1].

In contrast to synthetic generation, characterizing real workloads from large production cloud clusters provides direct insights into system behavior, though it is an arduous task due to data heterogeneity [2]. Scalable infrastructure, such as that based on Google’s Dataproc, has been proposed to analyze workload traces from environments like Google Cloud cluster-usage-traces-v3 [2]. These studies focus on the heterogeneity of workloads, variations in job durations, resource consumption, and overall resource availability in serverless platforms [2]. Such characterization is beneficial for cloud infrastructure providers and users managing computing resources, but it often addresses general cloud workloads rather than the specific demands of LLM serving [2].

Specific to LLM serving, practical systems must make non-trivial scheduling decisions to improve throughput by processing requests concurrently [3]. These decisions typically occur at two levels: a load balancer routes requests to servers holding LLM replicas, and an engine-level scheduler determines when to run, queue, or preempt requests [3]. A survey of scheduling techniques reveals that while literature-based schedulers often achieve good performance, they introduce significant complexity [3]. Conversely, schedulers in practical deployments are easier to implement and configure but often leave easy performance gains on the table [3]. This gap motivates the development of new scheduling techniques that are both easy to implement and effective on production workload traces [3].

Further analysis of LLM serving performance indicates that despite memory-intensive components like self-attention, end-to-end serving is compute-bound for most common workloads [4]. Existing serving engines often fall short of optimal compute utilization because heterogeneous operations—compute, memory, and networking—are executed sequentially within a device [4]. Frameworks like NanoFlow address this by exploiting intra-device parallelism to overlap the usage of these heterogeneous resources [4]. Similarly, enterprise applications such as summarization and RAG observe long prompts, leading to high prefill costs and response latency [5]. SwiftKV addresses this by reducing prefill compute through model transformation, allowing prompt tokens to skip later layers and incorporating KV cache compression [5]. These optimizations demonstrate that understanding the specific computational and memory characteristics of LLM workloads is critical for improving serving throughput and latency [4][5].

## KV Cache Reuse Patterns and Skewness

KV cache reuse has become a widely adopted optimization in LLM inference frameworks such as vLLM and SGLang, as well as among major providers including OpenAI, Microsoft, Google, and Anthropic [1]. While existing benchmarks often evaluate long-context methods in single-request scenarios, this approach neglects the full lifecycle of the KV cache in real-world use [1]. To address this gap, SCBench (SharedContextBench) was introduced as a comprehensive benchmark that evaluates long-context methods from a KV cache-centric perspective, covering generation, compression, retrieval, and loading [1]. This benchmark utilizes test examples with shared context across twelve tasks and two shared context modes to analyze capabilities such as string retrieval, semantic retrieval, global information, and multi-task processing [1].

The efficiency of KV cache reuse is further influenced by architectural choices in attention mechanisms. Multi-turn dialogues and context-intensive tasks challenge LLMs to integrate long histories without sacrificing generation quality [2]. Prefix LLMs can exploit historical context via bidirectional attention on prefix tokens, but they are rarely used in practice because multi-turn training requires many duplicated triplets [2]. Furthermore, the bidirectional prefix in these models prevents KV-cache reuse at inference time, which drives up cost and latency [2]. To retain the contextual understanding of prefix masking while preserving inference-time efficiency, the Intermittent Semi-working Mask (ISM) was introduced [2]. ISM injects sparse bidirectional attention into the causal backbone by alternating bidirectional attention over query segments with unidirectional attention over answer segments [2]. This design eliminates triplet expansion during training and maintains KV-cache reuse during inference, yielding latency comparable to standard causal LLMs [2].

Beyond single-model architectures, KV cache reuse is being extended to distributed and cross-model scenarios. In compound AI systems, different models often process inputs that share the same context prefix, yet enabling one model to reuse the prefix KV caches of a different model remains an open question [3]. DroidSpeak addresses this by enabling KV cache reuse across distributed nodes running inference of different LLMs, provided they share the same architecture [3]. This system selectively recomputes a few layers of the KV cache produced by another LLM and reuses the remaining layers, achieving negligible quality loss [3]. Additionally, the loading of these caches presents challenges due to limited I/O bandwidth, which constrains inference efficiency [4]. Cake, a novel KV cache loading system, optimally utilizes both computational and I/O resources in parallel to mitigate this bottleneck [4]. It employs a bidirectional scheduling strategy that dynamically balances KV cache computation and loading, ensuring efficient resource utilization [4]. Cake also incorporates an adaptive scheduling mechanism that integrates with non-prefix caching requests, improving system throughput and adapting to fluctuating resource availability [4].

The management of cache resources and eviction policies is critical for maintaining performance under skewed workloads. LLM inference systems often lack adequate resource cost models and optimization strategies to schedule requests with intermediate results residing in GPU memory [5]. To address this, a new cache replacement policy tailored for LLM inference was developed by adapting classic database techniques, which substantially saves GPU costs [5]. In broader cloud environments, distributed caches serve social networks and web applications at billion-user scales [6]. Cache-on-Track (CoT) proposes a decentralized, elastic, and predictive caching framework specifically tailored for small front-end caches serving skewed workloads [6]. CoT uses a heavy hitter tracking algorithm to continuously track the top-k hot keys and dynamically caches the hottest C keys out of the tracked keys [6]. Experiments show that CoT’s replacement policy consistently outperforms the hit-rates of LRU, LFU, and ARC for the same cache size on different skewed workloads [6].

Understanding content popularity and request patterns is essential for effective caching strategies. Active learning approaches have been proposed to learn content popularities and design accurate content request prediction models [7]. By modeling content requests as a demand matrix and employing query-by-committee matrix completion, these methods predict future missing requests to optimize caching while guaranteeing operational cache hit ratio requirements [7]. In information-centric networks, path segmentation-based hybrid caching schemes coordinate user access latency and network resource utilization [8]. This approach divides data transmit paths into user-edge and non-edge areas, applying heuristic caching in the former and content migration optimization in the latter to improve both cache hit ratio and access latency [8]. The fidelity of synthetic workloads is also crucial for performance evaluation, as synthetic workloads must closely resemble real application workloads to ensure credible results [9]. Lauca, an application-oriented transactional workload generator, studies key workload characteristics such as transaction logic and data access distribution to generate synthetic workloads with high fidelity [9].

## Cache Eviction Policies and Management Strategies

Managing the limited capacity of Key-Value (KV) caches in Large Language Model (LLM) inference is a critical challenge, with strategies broadly categorized into token-level, model-level, and system-level optimizations [1]. At the token level, several methods employ eviction policies based on attention scores to discard less critical KV pairs, though traditional approaches often degrade generation quality by causing context loss or hallucinations [2]. To address this, Scissorhands proposes the "persistence of importance" hypothesis, maintaining a fixed KV cache budget by storing pivotal tokens that significantly influence future generations [3]. Similarly, NACL introduces a general framework for long-context KV cache eviction that operates in a single operation during the encoding phase, combining accurate attention score statistics with diversified random eviction to alleviate attention bias [4]. Other token-level strategies include HashEvict, which uses locality-sensitive hashing to make pre-attention eviction decisions by computing Hamming distances between binarized projections, thereby reducing computational costs compared to attention-based methods [5]. Additionally, KVMerger proposes an adaptive KV cache merging approach that identifies similar key states within a sequence to compress the cache without significant performance degradation [6].

Beyond simple eviction, some approaches utilize dynamic allocation and compression techniques. D2O introduces dynamic discriminative operations that optimize KV cache size at both the layer and token levels, using a compensation mechanism to recall and merge discarded tokens based on similarity thresholds [2]. MiniKV further reduces memory footprint through a 2-bit layer-discriminative KV cache, achieving high compression ratios while maintaining accuracy for long-context tasks [7]. In contrast, StreamingLLM addresses the limitations of window attention by identifying an "attention sink" phenomenon, where retaining the KV states of initial tokens allows models to generalize to infinite sequence lengths without fine-tuning [8]. Model-level optimizations also contribute to cache efficiency; for instance, FastGen constructs an adaptive KV cache by profiling attention modules to evict long-range contexts on heads emphasizing local attention, while GQA reduces the number of key-value heads to speed up inference with minimal quality loss [9][10].

At the system level, cache management intersects with scheduling and hardware constraints. InfiniGen presents a KV cache management framework for long-text generation that speculates essential tokens to prefetch only necessary KV entries from host memory, improving performance in offloading-based systems [11]. ShadowKV addresses high-throughput long-context inference by storing low-rank key caches and offloading value caches to reduce memory footprint, employing an accurate KV selection strategy to reconstruct sparse pairs on-the-fly [12]. For resource-constrained environments, M2Cache utilizes mixed-precision and multi-level caching to enable LLM inference on older GPUs with limited High Bandwidth Memory [13]. Furthermore, database-inspired techniques have been adapted for LLM serving; one study develops cost models and a new cache replacement policy tailored for concurrent inference requests to optimize GPU resource usage [14]. While these system-level approaches focus on memory hierarchy and scheduling, workload-aware strategies are emerging to better align cache policies with specific request patterns. InstCache proposes a predictive caching mechanism for instruction-level caching, leveraging LLMs to reorder instruction representations to create spatial locality for predicting potential instructions [15]. Similarly, an intelligent router for LLM workloads uses reinforcement learning to schedule queries across instances based on workload characteristics, improving end-to-end latency by accounting for distinct prefill and decode phases [16]. These diverse approaches highlight the complexity of KV cache management, ranging from fine-grained token eviction to system-wide scheduling and predictive caching strategies [1].
