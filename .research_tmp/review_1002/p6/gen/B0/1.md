**Related Works**

**LLM Serving and KV Cache Management**
Efficient serving of Large Language Models (LLMs) is critical for cloud providers, where the Key-Value (KV) cache represents a significant memory bottleneck. Early systems like vLLM introduced PagedAttention to manage KV cache memory efficiently, reducing fragmentation and enabling flexible sharing of KV states across requests [1][23]. This approach significantly improved throughput by treating KV cache management similarly to virtual memory paging in operating systems. To further optimize memory usage, subsequent works have focused on sharing and reusing KV caches. ChunkAttention leverages prefix-aware mechanisms to share KV tensors among requests with common system prompts, improving memory utilization and self-attention speed [2]. Similarly, Prompt Cache accelerates inference by precomputing and reusing attention states for overlapping text segments, such as system messages and templates, thereby reducing time-to-first-token latency [4]. For retrieval-augmented generation (RAG) scenarios, CacheBlend addresses the challenge of reusing KV caches for non-prefix text chunks by selectively recomputing a subset of tokens to fuse cached knowledge, ensuring generation quality without full prefill costs [6].

**KV Cache Compression and Optimization**
Given the large memory footprint of KV caches, especially for long contexts, various compression and optimization techniques have been proposed. StreamingLLM introduces the concept of "attention sinks," observing that retaining the KV states of initial tokens allows window attention to generalize to infinite sequence lengths, which is crucial for streaming applications like multi-round dialogues [8]. H2O proposes a heavy-hitter oracle to identify and retain only the most important KV entries for generative inference, effectively reducing memory usage [9]. PyramidKV leverages the observation that attention patterns follow a pyramidal funneling structure, dynamically adjusting KV cache size across layers to retain only a small fraction of the cache while maintaining performance [11]. Additionally, KVQuant enables low-precision KV cache quantization, allowing for context lengths up to 10 million tokens with minimal perplexity degradation by employing per-channel and non-uniform quantization strategies [12]. InfiniGen further optimizes offloading-based systems by speculating essential KV entries to prefetch only necessary data from host memory, mitigating fetch overheads [10].

**Workload Characterization and Cache Replacement**
While many studies focus on algorithmic optimizations, there is limited understanding of real-world KV cache workload patterns. Previous characterizations often rely on synthetic workloads, which may not capture the complexities of production environments. In contrast, our work provides the first systematic characterization of KV cache workloads from a leading LLM service provider, revealing that reuse patterns are skewed and that single-turn request reuses are as significant as multi-turn ones. This aligns with broader trends in cloud computing where workload characterization drives system design. For instance, the characterization of serverless workloads at Azure Functions revealed significant variations in invocation frequencies, which informed resource management policies to reduce cold starts [25]. Similarly, in the domain of database and OS buffer management, extensive research has been conducted on cache replacement policies. Classical algorithms such as LRU-K [13], 2Q [14], EELRU [15], LRFU [16], LIRS [17], ARC [18], CAR [19], and CLOCK-Pro [20] have been developed to balance recency and frequency for optimal cache hit rates. More recent approaches like LHD maximize hit density [21], while learning-based methods like CacheUS adapt to workload dynamics [22]. Our proposed workload-aware eviction policy builds upon these insights, specifically tailored to the unique reuse characteristics of LLM KV caches, to improve serving performance under limited cache capacity.
