**Related Works**

**Natural Language Table Discovery**
Natural language (NL)-driven table discovery aims to identify relevant tables from large repositories based on user queries. Early approaches focused on ad hoc table retrieval, representing queries and tables in multiple semantic spaces to perform semantic matching [9]. With the advent of deep learning, methods began leveraging pre-trained language models (PLMs) to capture complex syntactic and semantic relations. For instance, BERT-based models were adapted to encode table content while considering structural constraints and input length limits [10]. More recent frameworks have addressed specific data lake scenarios, such as joinable table discovery. DeepJoin employs an embedding-based retrieval using PLMs to handle both equi- and semantic joins by contextualizing column contents [3]. Similarly, Starmie utilizes contrastive learning to train column encoders for dataset discovery, specifically optimizing for table union search and employing HNSW indices for acceleration [4]. Other systems, such as Solo, introduce self-supervised strategies to assemble training data and train discovery systems without human intervention, addressing the barrier of expensive data collection [5]. While these methods achieve strong accuracy, they typically rely on a traditional dense vector search pipeline, where errors in representation and indexing can accumulate and hinder final search performance.

**Differentiable Search Indexes**
To overcome the limitations of separate indexing and retrieval stages, the Differentiable Search Index (DSI) paradigm has emerged. DSI unifies these processes into a single Transformer model that maps string queries directly to relevant document identifiers (docids), thereby eliminating the error accumulation inherent in dual-encoder architectures [11]. This approach allows the model to answer queries using only its parameters, simplifying the retrieval process and demonstrating strong generalization capabilities [11]. Subsequent work has refined this paradigm to address specific challenges. NCI proposes a sequence-to-sequence network that generates document identifiers directly, utilizing a prefix-aware weight-adaptive decoder and semantic document identifiers to optimize recall [12]. A critical issue in DSI models is the data distribution mismatch between indexing (long documents) and retrieval (short queries). DSI-QG addresses this by representing documents with generated queries during the indexing phase, bridging the gap between the two processes [13]. Furthermore, CorpusLM integrates generative retrieval with closed-book generation and retrieval-augmented generation (RAG) within a unified language model, exploring the relationship between generative retrieval and downstream knowledge-intensive tasks [14]. These advancements highlight the potential of parametric indexing to achieve deep query-document interactions, a principle we adapt for table discovery.

**Continual Learning in Generative Retrieval**
Dynamic table repositories require systems to accommodate continual indexing without degrading performance on existing data. Traditional continual learning approaches often suffer from catastrophic forgetting. In the context of generative retrieval, DSI++ introduces methods for updating Transformer memory with new documents, addressing the static corpus assumption of earlier models [15]. CLEVER further advances this area by proposing a model for continual learning over dynamic corpora. It employs Incremental Product Quantization to encode new documents with low computational cost and utilizes a memory-augmented learning mechanism to preserve knowledge of previously indexed documents [16]. These techniques are crucial for maintaining retrieval accuracy as the corpus evolves. Our work builds upon these foundations by applying differentiable search index concepts specifically to the domain of table discovery, introducing a parameter isolation strategy to mitigate forgetting while enabling deep query-table interactions through synthetic query generation.
