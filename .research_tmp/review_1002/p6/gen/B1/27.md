## Related Works

**Table Discovery and Retrieval**
Natural language (NL)-driven table discovery aims to identify relevant tables from large repositories based on NL queries. Early approaches focused on ad hoc table retrieval, representing queries and tables in multiple semantic spaces and using supervised learning to match them [1]. Subsequent work leveraged deep contextualized language models, such as BERT, to encode table content while considering structural constraints, significantly outperforming previous state-of-the-art methods [2]. To handle complex table layouts with nested headers and diverse dependencies, Graph-based Table Retrieval (GTR) introduced multi-granular graph representation learning, converting tables into tabular graphs processed by Graph Transformers to capture both cell content and layout structures [3]. In the domain of data lakes, specific challenges such as joinable table discovery have been addressed by models like DeepJoin, which uses pre-trained language models to embed columns for equi- and semantic joins, achieving logarithmic search times via approximate nearest neighbor search [4]. Similarly, Starmie employs contrastive learning to train column encoders for dataset discovery, utilizing HNSW indexing to accelerate table union search [5]. Other systems, such as Solo, utilize self-supervised approaches to enable data discovery via natural language questions without expensive human-labeled training data [6].

**Generative Retrieval and Differentiable Search Indexes**
Traditional dense retrieval pipelines follow a representation-index-search paradigm, where errors in representation and indexing accumulate to affect final search accuracy [7]. To address this, the Differentiable Search Index (DSI) paradigm emerged, using a single Transformer model to encode corpus information directly into its parameters, mapping string queries to document identifiers (docids) without a separate index [7]. This approach simplifies retrieval and allows for direct query-document interaction. However, early DSI models suffered from data distribution mismatches between indexing (long documents) and retrieval (short queries). DSI-QG mitigated this by representing documents with generated queries during the indexing phase, improving performance in mono- and cross-lingual settings [8]. Further advancements include the Neural Corpus Indexer (NCI), a sequence-to-sequence network that generates relevant document identifiers directly, employing prefix-aware decoding to enhance recall [9]. More recently, CorpusLM proposed a unified language model that integrates generative retrieval with retrieval-augmented generation, using ranking-oriented DocID list generation to improve factual accuracy in knowledge-intensive tasks [10].

**Continual Learning for Dynamic Corpora**
A critical limitation of static generative retrieval models is their inability to handle dynamic corpora where new documents are continuously added. Existing methods often assume a static collection, leading to catastrophic forgetting when new data is introduced [11]. To address this, the CLEVER model was proposed for continual learning in generative retrieval, introducing Incremental Product Quantization to encode new documents with low computational cost and a memory-augmented learning mechanism to preserve knowledge of previous documents [11]. Additionally, DSI++ has been developed to update Transformer memory with new documents, addressing the need for incremental indexing in dynamic environments [12]. These developments highlight the growing importance of maintaining retrieval accuracy while accommodating the continual evolution of data repositories.
