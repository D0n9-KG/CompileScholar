## Related Work

**Pipeline Architecture**
Existing approaches to natural language-driven table discovery primarily rely on the traditional dense vector search pipeline, which decouples the representation and indexing phases from the search phase. Methods such as DeepJoin [3], Starmie [4], and dense retrieval for open-domain QA [6] employ separate modules for embedding tables and performing approximate nearest neighbor search, a design that inevitably leads to error accumulation between the indexing and retrieval stages. In contrast, a distinct line of research explores alternative architectures that diverge from standard dense vector search. These include self-supervised learned discovery systems [5], graph-based retrieval frameworks [8], hybrid sparse-dense retrieval pipelines [9], and bi-encoder models utilizing BERT contextualized embeddings [10]. More recently, a paradigm shift toward unified encoder-decoder models has emerged, where the search index is made differentiable. Pioneering works like the Differentiable Search Index (DSI) [11] and the Neural Corpus Indexer (NCI) [12] map queries directly to identifiers using a single Transformer model, a strategy further extended by DSI-QG [13], CorpusLM [14], DSI++ [15], and CLEVER [16]. While these unified models eliminate the error accumulation inherent in separate representation and indexing modules, they often focus on document retrieval or general corpus indexing. Birdie stands out by adapting this unified differentiable search index architecture specifically for table discovery, leveraging the structural nuances of tabular data within a single encoder-decoder framework.

**Query-Table Interaction Mechanism**
The mechanism for aligning query semantics with table content varies significantly across prior work. The majority of dense retrieval methods, including DeepJoin [3], Starmie [4], dense retrieval for QA [6], and ad hoc table retrieval using semantic similarity [9], rely on shallow cosine similarity between static embeddings. This approach limits the depth of interaction between the query and the table structure. Other methods employ more complex matching strategies, such as relevance models with synthetic questions [5], Graph Transformer matching [8], or bi-encoder independent encoding of query and table [10]. However, these methods still generally treat the query and table as separate entities to be matched post-encoding. In contrast, recent generative retrieval approaches, including DSI [11], NCI [12], DSI-QG [13], CorpusLM [14], DSI++ [15], and CLEVER [16], achieve deep semantic alignment by directly generating table or document identifiers. This direct generation process allows for richer interaction between the query and the index parameters. Birdie aligns with this latter group by enabling deep semantic alignment through the direct generation of table identifiers, thereby facilitating a more effective alignment of query semantics with table structures during the decoding process.

**Table Representation Strategy**
How tables are represented within the index is a critical design choice that impacts retrieval accuracy. Traditional dense methods typically represent tables as fixed-length dense vector embeddings [3, 4, 6]. Alternative strategies include using table representation strategies for self-supervised models [5], multi-granular tabular graphs [8], multi-space semantic representations combining sparse and dense features [9], and BERT-encoded table content with structure awareness [10]. In the domain of differentiable search indices, representation strategies have evolved to include document identifiers encoded in model parameters [11], ranking-oriented DocID list generation [14], and incremental Product Quantization docids [16]. Notably, the Neural Corpus Indexer [12] and DSI-QG [13] introduce prefix-aware identifiers with synthetic query generation, a strategy that creates a learnable mapping between natural language queries and unique table identifiers. Birdie adopts this specific representation strategy, assigning each table a prefix-aware identifier and leveraging a large language model-based query generator to create synthetic queries. This approach distinguishes Birdie from methods relying on generic embeddings by allowing the model to memorize the index through the mapping of synthetic queries to identifiers.

**Continual Indexing Strategy**
The ability to update the index with new tables without degrading performance on existing ones is a significant challenge in dynamic repositories. Most prior work on table discovery and generative retrieval does not explicitly address continual indexing or assumes a static corpus. However, recent advancements in generative retrieval have begun to tackle this issue. DSI++ [15] addresses the problem of updating Transformer Memory with new documents, while CLEVER [16] proposes a model for continual learning that uses memory-augmented learning with incremental quantization to preserve old knowledge while indexing new documents. Despite these efforts, there remains a gap in the literature regarding specific strategies for mitigating catastrophic forgetting in the context of table discovery using differentiable search indices. No cited prior work employs parameter isolation to mitigate catastrophic forgetting in this specific domain. Birdie introduces a novel index update strategy via parameter isolation, which effectively mitigates the issue of catastrophic forgetting, thereby accommodating the continual indexing of dynamic tables more robustly than existing continual learning approaches.
