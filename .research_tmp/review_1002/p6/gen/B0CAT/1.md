**Related Works**

**KV Cache Memory Management and Sharing**
Efficient LLM serving relies heavily on managing the substantial memory footprint of the Key-Value (KV) cache. Foundational systems like vLLM introduce PagedAttention to eliminate memory fragmentation and enable flexible sharing of KV states across requests [1][23]. To further optimize memory utilization, recent works focus on prefix-aware sharing and modular reuse. ChunkAttention structures KV tensors into a prefix tree to share common system prompts across multi-tenant requests [2]. Similarly, Prompt Cache precomputes and stores attention states for reusable text segments, such as system messages and templates, to reduce time-to-first-token latency [4]. For retrieval-augmented generation (RAG), where context chunks are not always prefixes, CacheBlend fuses precomputed KV caches from multiple text chunks by selectively recomputing a subset of tokens [6]. While these methods significantly improve memory efficiency and throughput, they primarily address the structural organization and sharing of KV states. They often assume static or predictable reuse patterns and do not deeply characterize the dynamic, workload-dependent eviction behaviors required for optimal cache management in diverse production environments.

**KV Cache Compression and Pruning**
To mitigate the memory constraints of long-context inference, several approaches employ KV cache compression and pruning. StreamingLLM leverages the "attention sink" phenomenon, retaining only the KV states of initial tokens and the most recent window to enable infinite sequence length generalization [8]. H2O identifies "heavy hitter" tokens that contribute significantly to attention scores and retains only these, discarding the rest to save memory [9]. PyramidKV observes that information flow in LLMs follows a pyramidal pattern, allocating more cache to lower layers and less to higher layers to maintain performance with significantly reduced memory [11]. InfiniGen dynamically manages KV cache by speculating essential tokens for prefetching in offloading-based systems, thereby reducing host memory fetch overhead [10]. KVQuant focuses on quantization, using per-channel and non-uniform methods to achieve sub-4-bit precision for KV activations, enabling million-token context lengths [12]. Although these techniques effectively reduce memory pressure, they typically apply uniform or layer-specific compression strategies. They do not account for the specific temporal and frequency-based reuse patterns of individual requests, potentially evicting or compressing data that would have been reused soon, thus limiting their effectiveness in latency-sensitive serving scenarios with limited cache capacity.

**Cache Replacement Policies**
The management of finite cache resources in LLM serving draws parallels from classical operating system and database buffer management. Traditional replacement policies such as LRU-K [13], 2Q [14], EELRU [15], LRFU [16], LIRS [17], ARC [18], CAR [19], and CLOCK-Pro [20] have been extensively studied for their ability to balance recency and frequency. More recent advancements include LHD, which maximizes hit density [21], and CacheUS, which uses reinforcement learning to adapt replacement policies [22]. In the context of LLMs, CachedAttention specifically targets multi-turn conversations to improve cost-efficiency through caching [3][24]. However, the application of these general-purpose policies to LLM serving has been limited. Most existing studies rely on synthetic workloads or assume specific request structures, such as strict multi-turn dialogues. There is a lack of systematic characterization of real-world KV cache reuse patterns, particularly regarding the skew in reuse across single-turn versus multi-turn requests and the predictability of reuse times within specific request categories. This gap hinders the design of workload-aware eviction policies that can maximize hit ratios under realistic, heterogeneous production workloads.
