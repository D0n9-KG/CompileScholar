# F24 设计简报 v0.1 — 确定性表格解析通道（待用户评审）

**来源**：PSFIX/COACH2 一夜三轮实测的败因转化（f23 归因 48% 抽取端全在表格 + 教练轮2 空壳崩解档案 + mw1P 碎片表诚实溢出）。**状态**：设计简报，未实现；KB v3 重抽不含此通道（其产出未来以增量层并入，零 LLM，不触发重抽——KBV3-PREREG 判决规则已预留）。

## 一、问题：LLM 抽表格的四个实测失效形态

| 形态 | 实测档案 | 教练可修？ |
|---|---|---|
| 行覆盖不全（只抽代表行） | nN8T §5/§6 表 6 个 gold 值两协议均未回收 | ✗（COACH2 C2-3 判负） |
| 枚举强制→空壳崩解（quote/表头逐字全对、五字段全空×40） | coach2 dropped_b2 | ✗（教练天花板第三例） |
| 碎片表（mineru 单元格融合"91.691.4"/colspan 断裂）诚实溢出 | mw1P 3 表、pPh9 融合格 4 条 | ✗（语料级，任何协议绑不了） |
| 列绑定串位（A7：值/列对、subject 绑邻列） | nN8T 15 条（IL-2 已确定性清理脏维度） | 半（1e 后未再复发但未根证） |

**共同洞察**：失效全在"结构搬运"环节，而 LLM 恰恰在**逐字抄行**上可靠（空壳记录的 quote+table_header 都抄对了；FG6 救回的 95 条引文全逐字）。HTML/管道表的行列解析是确定性问题——**结构交给解析器，LLM 只留在语义位**。

## 二、设计 sketch（v0）

**管线**：源文本表格块检出（`<table>` HTML + 管道表）→ 确定性解析（rowspan/colspan 展开、多级表头路径合并、行头识别）→ 逐数据单元格出 result 记录：

- `quote` = 数据行整行逐字（天生过 FG6 数字门+quote 门——值必在引文内，构造性保证）
- `table_header` = 表头行逐字
- `method_ref.surface` = 行头；`measure.metric` = 列头路径（如 "NLP > QA RoBERTa-L"）；`measure.value` = 单元格逐字；`loc` = 字符定位
- `direction/unit` = 表头 ↑↓/(%)/± 确定性正则，取不到留空
- **碎片表诚实跳过**：融合单元格（同格多数值无分隔）/断裂 colspan → 不猜、进可见残差（与 1e"数不准列位不输出"同哲学，但由解析器判定而非模型自觉）

**四个难题（诚实列，v0 各有保守方案）**：

1. **role（main_result/baseline_comparison/ablation）不可确定性判定** → v0 保守规则：行头模糊匹配本篇 method_identity 锚（cards，FX-B 同源）→ main_result；否则 baseline_comparison；无锚论文（理论型）→ baseline_comparison 兜底+`role_provisional` 标记。备选：每表一次轻量 LLM 角色判定（结构化输入，~200 tokens/表——成本可忽略但引入 LLM 依赖，v0 不做）。schema v1.3 联动：role 是否对该通道放宽为可选=仲裁议题。
2. **epistemic（自己做的 vs 转引他人）**：canary T2 陷阱测的正是这个 → v0 规则：章节上下文（Experiments/Evaluation 节内→demonstrated；Related Work 节内→cited）+行头=本篇方法→demonstrated 优先。判错的代价对称披露。
3. **与 LLM 通道记录的去重**：LLM 1b 协议仍抽表（且抽得动的表质量已验证）→ v0 策略：解析器记录**先行入库**，LLM 记录经既有 `_rid` 指纹（method|value）去重合并、最长 quote 胜；重叠不一致时（同格不同绑定）打 `conflict` 标进人工抽读样本——不一致率本身就是两通道的交叉验证指标。备选（更激进）：改协议让 LLM 完全跳过表格——大改，v0 不做。
4. **哪些表算"基准表"**：v0 只收数值单元格表（≥1 数值列+可识别行头）；纯文本分类表/符号表跳过（notation 记录走 LLM 通道不变）。

## 三、验证计划（全零 LLM 成本，实现后跑）

1. **gold 直测**：PS16 全 16 篇跑解析器 → 1a 仍缺 20 值中位于可解析表的回收数（当前上限判读：nN8T 6+lXuB 2+s7xWe 1+pPh9 附录若干；碎片表值预期仍缺=如实报）
2. **交叉一致性**：与 KB v3 LLM 表格记录重叠单元格绑定一致率（目标 ≥95%，低于即解析器有系统 bug）
3. **canary 地面真值**：Table 1/2 全 12 单元格解析结果 vs 已知真值 100%；T4/T5 逻辑对解析器记录同样生效
4. **人工实读**：30 条分层抽样（含 conflict 标全量）≥4.0/5 零编造
5. **AirQA 先行抽验**：官方 processed_data 表格 HTML 解析质量抽 20 篇（尽调已证比 mineru 干净；碎片率读数决定 AirQA 端配置）

## 四、风险与闸

- **解析器 bug 批量产错绑**（最大风险：确定性错误会规模化）→ 三重闸：构造性 quote 逐字（后检复验）+canary v2 在岗+交叉一致性指标；任何验证红灯=通道不上线，LLM 通道不受影响（增量层设计=可整体摘除）
- 表头跨 chunk 断裂（行与表头不同 chunk）→ 解析器在**全文级**跑（非 chunk 级），天然免疫——这也是对 LLM 通道的结构性优势
- 成本：实现+验证 ≈0 LLM；生产期 0 LLM/表
