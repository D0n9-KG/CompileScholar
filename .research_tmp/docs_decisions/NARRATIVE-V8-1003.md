## 1. 一句话主张

现有文献系统把论文编译成**内容**（片段、主张、三元组、单篇卡片）；我们把一个领域编译成**状态**——只有把多篇论文
合在一起才成立的东西：方法族与成员、族内共同局限与开放问题、跨论文的比较关系——并证明 agent 在这个状态之上
检索和写作，比在平面片段上更好地回答领域级问题。

### 3.2 消融（决定叙事能否立住，必须预注册）
1. **去状态层**：只保留记录级检索（关掉方法族/族级局限/比较关系展开）。
2. **去 KB**：只留外部检索 + 引文扩展（= 强检索 agent 基线，同管线）。
3. **去引文扩展**、**去外部检索**。
4. 长度：写作无上限 vs 旧 700–1100 词（报告，不作卖点）。

判读规则（预注册）：若消融 1 无正贡献（CI 跨零），主张收缩为"编译证据库 + 逐字引用 + 结构化写作管线"，
领域状态降为分析章。

### 3.3 领域层直接检验（区别于 LKM/ScholarStack 的关键证据）
留出 15–20 篇综述（不进 KB），只给其引用论文：系统构建领域状态 → 与综述作者的判断对照（方法族划分、族内共同局限、
开放问题），nugget 式召回/精度；规模 10/30/全量引用论文三档。金标来自综述原文，不由我们生成。

### 3.4 分析章（已有数据，可直接写）
- **组织轴在小证据量下无效**：DSB oracle（给齐 ~18 篇参考文献）下，目标诱导维度 −0.110*、完整枚举 −0.070*、主题聚类 +0.002、
  段尾定位 +0.001、DeepScholar-base 官方流程 −0.054*（p6/p7）——组织的价值依赖证据规模，这正是 3.3 规模曲线要回答的。
- **失分层级**：DSB 上 harness 失分 61% 在检索层（p5，人工复核校准），解释为什么引文扩展必要。
- **评测效度**（作为"实验设置/注意事项"写，不作主贡献）：CS2 官方 simplified_eval 无长度项、IR 与长度强相关；
  截止泄漏（未强制时 harness 42/93 题引 2026 论文）；GPTR 适配器修复前后 0.763→0.557；判分噪声（同输入重判 |Δ| 0.043）。
