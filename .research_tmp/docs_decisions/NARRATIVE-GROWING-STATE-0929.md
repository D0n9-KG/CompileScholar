# 叙事 v6：会生长的领域世界状态（2026-09-29 定稿方向）

用户裁定：引文意图边被占（很多工作在做）——砍掉作为卖点。
保留主线："**一个会生长、知道自己缺什么、按意图定向探索的领域世界状态**"。

## 四件套主线（相对 LKM/ScholarStack 的差异化）

**1. 会生长（backflow 深读回流）——用户关键澄清（09-29）**
**自生长=系统运行时自己扩库（deep_read+backflow），不是跟着 benchmark 补库**
（按题生长=作弊红线，过拟合纪律）。要打"世界状态"就必须证明系统本身
具有持续扩充与自生长的能力。
vs LKM 的静态 40M 预编译——我们的库随使用生长：第 N 题的深读成果成为
第 N+1 题的库存（跨会话持久化，EviMem 只占临时闭环半环）。

**生长模式与答题模式的分离（用户关键架构裁定 09-29）**：
**自生长不是为 benchmark 服务**——benchmark 验证的是系统的通用能力。
两个模式显式分离：
- **答题模式（benchmark 用）**：生长开关关闭。检索模块仅服务于当前
  问题（现状：V4 触发的外部检索是答题行为，不是建库行为）。
  这保证 benchmark 分数的解释干净——不靠库的生长红利刷分。
- **生长模式（能力主张用）**：开关开启。系统持续外部检索→抽取→
  入库→backflow 挂谱系——库随运行自主扩张。这是"世界状态"主张的
  本体：状态不仅在查询时被消费，在运行中被主动扩充。
实验证明的是生长模式的能力本身，与答题模式的分数解耦。

**生长能力实验（独立于 benchmark 的自建协议）**：
关键约束实测：CS2 100 题主题几乎零重叠——生长实验不能在 CS2 做
（也不该做——模式分离后 benchmark 就是关着生长跑的）。
协议（累积 KB 回放 + 自建领域序列）：
1. 载体：DSB 子领域聚集（cs.IR 21 题/cs.CV 16 题）或自建同领域
   递进问题序列（20-30 题）
2. 生长模式跑题序（KB 只增），保存领域起点/终点的 KB 快照
3. 判据（分两层）：
   a. **生长行为本身的度量**：新增记录数/新增谱系边数/backflow 率/
      抽取质量抽查——证明"系统确实在自主扩库"
   b. **生长的效用**：同题在初始 KB vs 生长后 KB 的检索命中/得分差
4. 反作弊声明：题序预注册固定、KB 单调只增、无人工干预
待修：backflow 字段适配 bug（P0-1）——生长机制现在断裂
（54/66 篇深读没回流），修复是生长实验的前置。

**2. 知道自己缺什么（typed absence + gap_status 动态比对）**
vs ScholarStack 无 absence、LKM 的 gap records 是静态记录——我们的缺口
（a）有类型三态（b）**问题驱动的动态差集**（gaps×证据满足度，每题重算），
缺口的文本直接变成下一轮检索词。
实验：缺口题触发率/救回率消融（V4 前后对照已在积累）。
待修：gap_status 层（P0-4）+ 中文缺口清洗（P0-5）+ 派生缺失通道（空词表）。

**3. 按意图定向探索（缺口→检索词闭环 + 意图边定向遍历）**
查新结果（09-29 补查，一手验证）比预期好：
- "把引文意图做成边类型"已被占（Typed Claim Network 2605.30966 的
  Critique/Adoption/Benchmark/Neutral 四类边；Trust-Aware 2607.06528
  204万边规模化）——**但两篇均非 agent 检索用途**
- **"意图过滤的定向引文遍历用于 LLM agent 文献发现" = arXiv 0 命中空位**
  （PaperQA2 的 citation chasing 意图盲——重叠数过滤；Typed Claim
  Network 明确不做 agent 遍历且自己检索实验 n=15 不显著）
- 精确表述："首次意图过滤的定向引文遍历用于 agent 文献发现（沿
  extends/improves 找演化链、跳过背景引用）"——可主张
- 我们的谱系边类型（6类）比文献所有方案细（SciCite 3类/claim network 4类）
- S2 intents 覆盖 0/55、OpenAlex 裸 ID——现成数据不可依赖，自建是
  唯一路径（工程必要性论证）
保留核心：**编译状态指挥检索行为**（gap_status 输出直接是检索查询 +
谱系边类型定向遍历），vs 竞品编译物只被查询。
实验：闭环消融 + 意图边遍历 vs 裸引文遍历消融。
风险：Typed Claim Network（Ding 等 2026-05）同团队做 agent 版概率高——
投稿前监视清单加这篇。必引：1904.01608/2605.30966/2607.06528/
2409.13740/2606.20235。

**4. 状态可追溯（as_of 时间切片 + resolved_by 缺口生灭）**
vs 竞品全部无时间维度——缺口不仅有类型还有**生命周期**（被解决→标记
resolved_by→保留历史链），知识有 as_of 切片（领域在任意时点的状态）。
实验：缺口生灭追踪率（有明确解决关系的缺口对，系统能否追踪到）。
待修：谱系边年份回填（P0-3，2406 边全 None）+ absence 语义失效（P0-2）。

## 措辞纪律
- 不说"我们发明了意图分类/缺口分析"——组件都有单点先例
- 卖点是**组合+闭环验证**："编译-探索-沉淀的完整闭环，每个组件收益单独可证"
- 引文意图相关工作（SciCite 一系）在 related work 引用，作为我们
  谱系边类型的文献支撑（不作为创新主张）
