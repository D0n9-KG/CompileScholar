## 0. 结论先行

1. **一半以上的问题不是"修几个 bug"，而是架构选择本身错了**，所以多数层判"重构"，只有抽取记录和外部检索封装保留。
2. 最大的三个结构性错误：
   - **答题循环和最终报告是脱节的**：agent 写笔记，独立 LLM 再编译成报告，答案字段被丢弃；笔记超长被机械剪到 3000 字——
     报告证据面上限≈15 行笔记。这一项同时解释了 IR 低（内容少）和 CT 高（只写有锚的少量句子）。
   - **"状态层"从未真正可用**：card 结构写错一层（31b 起全假阴性）、lineage 回放 41/41 空、findings 字母序截断、
     claim_type 过滤失效、survey/hub 层 75% 的记录所属论文不在 manifest（引用解析不了）、深读记录不进视图。
   - **评测口径与完整性**：KB 的 demand_core 层（793 篇）由 dev 题面检索建出；快照不冻结（text_index 跨 run 累积）；
     知识截止全臂未执行；GPTR/OpenAI DR 适配器各有 bug；global 不是官方口径；harness 超时题被剔除。
3. 修完后能不能赢 harness 不保证；按机制估计的最大杠杆依次是：去掉长度上限+放开笔记容量（IR）、修好 KB 检索排序与状态
   工具（IR/AP）、引文扩展补外部覆盖（IR）、截止统一执行（对手侧）。

## 2. 每层判决：修 or 重构

| 层 | 判决 | 理由 |
|---|---|---|
| 单篇抽取记录（粗抽/深读/综述抽取） | **保留 + 清洗** | quote 逐字保真 29/30、锚逐字节对齐（AUDIT-0928）；数据层本身干净 |
| manifest / 论文注册 | **重建** | 统一一份 paper registry，覆盖全部层（含 survey/hub），修 K1/K2 |
| 实体同一性 | **重做** | 泛词污染、绑定率低、两键空间；改为"候选生成 + LLM 判同一 + 黑名单 DF 阈值"并落成单一编译步 |
| 视图编译 | **重构** | 单一入口、单一真相源、幂等；深读记录进视图；删除无消费者视图 |
| 查询工具 | **重构（大幅缩减）** | 13 个工具→4–5 个；相关性排序（BM25+向量+RRF）；明确的空/弱命中语义 |
| 答题循环 | **抛弃重写** | 2784 行补丁堆、13+ 注入、判分只吃笔记——无法修成干净方法；改为"规划→检索→证据表→直接写报告"的短管线 |
| 出口编译 | **重写** | 报告由主模型基于证据表一次写成，引用在写作时绑定（不再事后解析 82% 失败的锚） |
| 生长/backflow | **在新抽取+检索模块上重做，用来建热启动库**（用户 10-03 澄清） | 设计逻辑对（缺口→下一轮检索目标→扩库）；旧实现败在目标信号太泛（缺口原文拼检索词，1/24 解决）。新目标信号=引文前沿（库内论文高频引用但库里没有，p8：≥2 篇共引候选命中率 5.8% vs 单引 0.7%）+ 缺口文本检索为第二信号。backflow 关系升级（17/20 错）暂不接 |

| 判分管线 | **修** | 官方口径、metadata、截止、适配器对等、超时计 0 |

## 3. 新架构（v-next）

```
离线编译（一次，可复现，带哈希冻结）
  语料：截止过滤后的论文（去掉 demand_core 层；保留综述骨干 + hub + 领域通域层）
  ├─ 单篇记录（保留现有抽取）
  ├─ paper registry（全层统一元数据：标题/年份/arXiv/DOI/层别）
  ├─ 实体同一性（候选 → LLM 判同一 → 规范实体 + 别名）
  └─ 领域状态视图（只保留有消费者的三类）
       · 方法族与成员（来自综述 taxonomy 记录 + 实体归一）
       · 族级局限 / 开放问题（survey_gap + 深读 absence，带出处）
       · 比较关系（survey comparison + lineage，关系词表归一）

答题（每题，无写库）
  1. 规划：题面 → 3–6 个子问题（保留现有分解，修正 id/覆盖判定）
  2. 检索：每个子问题并行
       KB：混合检索（BM25+向量）+ 状态视图展开（命中方法族→族内成员、族级局限）
       外部：Sciverse/S2 语义 + 引文扩展（种子参考文献按被引频次排序，p8 已证召回翻倍）
       全部服务端强制截止日期
  3. 证据表：去重、按子问题归档、每条带逐字 quote 与出处（不再有 3000 字剪裁）
  4. 写作：主模型按子问题直接写报告，引用在写作时从证据表绑定（无长度上限；有依据的事实句才进）
  5. 自检：确定性检查每个引用 id 可解析、每节有证据（不再用 27B 自我反思）
```

**与论文叙事的关系**：领域状态视图（方法族/族级局限/比较关系）是"更上一层"的载体；消融=去掉状态视图展开、
去掉整个 KB 只留外部检索。若消融显示状态视图无正贡献，叙事退为"编译证据库 + 逐字引用"。

## 5. 风险
- 重写答题管线后 dev 分数短期可能下降（旧系统的补丁有些确实在起作用）——以轨迹验证机制，不以单批分数决策。
- 去掉 demand_core 层后，CS2 上 KB 覆盖会变差；需要靠引文扩展外检补回，这本身是诚实的代价。
- 状态视图消融可能无正贡献——提前定好退路叙事（§3）。
- 算力：单个 27B 实例，dev/test/DSB/Multi 都要排队，test 期间需要整块时间。
