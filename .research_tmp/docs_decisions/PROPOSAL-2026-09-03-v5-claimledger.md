# 提案 v5：ClaimLedger——论文原生的结构化知识表示及配套抽取/更新体系

（v1 认知状态地图被否决；v2 双层方案被判重设计；v3/v4 审计器方向被用户判定"创新不足、无 PK 面"；本 v5 是方向重启——**从论文文体的真实结构出发设计表示原语**，而不是从"别人没做什么"出发。两个支撑调研：本地现象测量（5 篇 DRL 论文 109 条 gold 边逐句人工分析）+ 外部文献调研（体裁学/论证挖掘/语义出版三条学术线），两路独立汇合于同一诊断。）

## 1. 问题：现有表示与论文信息结构的系统性失配

**核心主张：知识超图/三元组 KG 的语义原语（实体+关系）不匹配科学论文的信息结构。论文的原生信息单元是"带认识状态的条件性主张"，用关系边表示它在四个维度上系统性失真。**

失配的证据（两路独立汇合）：

| 维度 | 本地实测（109 gold 边逐句分析） | 外部佐证 |
|---|---|---|
| **条件性** | 30 条精读 67% 带实验条件限定，且大部分隐式（词汇标记仅命中 25%）。PER "outperform DQN on 41/49 games"——去掉条件主张由真变假 | 论文条件性有专门 shared task（CoNLL-2010 hedge） |
| **认识状态** | 同一 influences pattern 混杂已实证/机制论证/纯假设/引用他人四种等级（"We hypothesize" 与 "This demonstrates" 同种边） | Argumentative Zoning/CoreSC 修辞角色线 25 年历史 |
| **归属** | 自己实验结论 vs 转述他人结果同为 improves 边——证据强度差异被抹掉 | micropublications 2014 年已分 claim/evidence/argument 三层 |
| **时间/版本** | 方法名不变内容变（PER 优先信号被 Rainbow 换成 KL loss）；沉默是信息（PER 用 target network 但 0 次提及）；实测方法状态词汇 10 种远超 pattern 体系 | 论文=对已有知识的 delta（体裁学定论），静态边无法表达 |
| **证据位置** | 数值证据 80% 在表格/图（句内仅 14%），靠指针绑定——句子级 evidence_span 系统性丢失 | SciVer 证明证据大量在图表 |
| **多重实现** | 同一主张在摘要/结果/讨论出现三次、措辞与认识强度都不同 | AZ/SciFact 的 rationale 结构依赖它 |

**为什么失配不是小事**：这四个维度恰好是科研智能体最需要的（条件对齐的矛盾检测、方法先验、认识论卫生、SOTA 跟踪）——表示层的失配直接传导为下游能力缺失。RAG 的文本块单元同样没有这些维度。

**超图的定位修正**（重要设计判断）：超图作为**序列化/索引容器**是无辜的——n-ary 参与者确实是论文结构的一部分（SciREX 4-ary 是社区被迫承认的证据）。错误在于**让容器的形状定义了语义原语**（超边=实体集 → 认识状态/条件/论证方向无处安放被压扁丢失）。本方案：超图降级为序列化层，语义原语升到记录层。现有 kernel/n-ary 存储/演化机制全部保留。

## 2. 表示设计：五种带认识论类型的记录 + 四层关系

### 2.1 基本单元（从论文信息类型学正推，不从图形状倒推）

1. **Claim Record（主张）**：被承诺的断言
   - 认识状态：`empirical / mechanistic / hypothetical / attributed`（四种等级，实测混于同一 pattern 的四种）
   - 确定性限定词（hedging）
   - **多 span 锚点**：同一逻辑主张在 abstract/results/discussion 的多处 verbatim 实现（多重实现性首次一等建模）
   - delta 链接：extends / contradicts / refines 哪些已有 claim
2. **Evidence Record（证据）**：一次测量/观察——数值、不确定性、统计检验、**模态**（text/table/figure，数值 80% 在图表的实测现实）
3. **Method Record（方法）**：可执行知识——步骤、超参、环境、依赖 artifact；内部为**带序步骤图**非平面边
4. **Context Record（适用域）**：条件作为**可组合独立对象**（数据集/规模/干预/机制条件/权衡子句），支持交/差/扩展运算
5. **Artifact Record（制品）**：数据集/模型/代码等可指名复用单元

五种记录直接对应 CoreSC 的信息类型划分（Method/Experiment/Result/Conclusion/Background——25 年修辞角色研究的可计算证明），每种都有独立抽取文献支撑。

### 2.2 关系：四层，不许跨层混边

```
论证层（claim↔claim）: extends / refines / contradicts / replicates（继承 ScholOnto 2000 边集）
证据层（claim→evidence）: supports / limits
操作层（evidence→method→artifact）: produced_by / configured_with
作用域层（任何 record→context）: 绑定适用域
```

现行系统所有关系混在无边型约束的超图里——"A 在 D 上优于 B"（有证据的主张）与"A 使用技巧 X"（操作分解）是同构的边。分层后的结构红利：**比较不再是边的类型而是一等 Claim Record**（A vs B under context，带 margin/显著性/检验）——improves-vs-compares 类型混淆（我们的头号失效模式）有了结构解法，比较句在 Results 区有强数字线索，抽取难度骤降。

### 2.3 时间、版本、更新策略

- **append-only 账本**：claim 真值 = (context, 语料库状态) 的函数，每条版本 = (断言, context, 证据集, 出处)
- **SOTA = 物化视图**：不是节点属性而是对账本的查询（按 task-context 族取最新最强）——"读一次的事实"与"持续跟踪的状态"第一次有表示层区分依据
- **方法版本节点**：名字不变内容变的情况（PER 换信号）显式版本化；沉默继承（不提及但使用）可表示为方法依赖图的传递闭包
- **更新策略**：语料流驱动 append + 矛盾检测触发 claim 族分叉 + 物化视图重算

## 3. 抽取设计：role-first 两阶段

**利用现有实测病灶反推出的结构性解法**：

- **阶段一（廉价分类）**：修辞角色/记录类型识别——CoreSC 自动分类 F1 0.7+ 的成熟任务，genre 线索强
- **阶段二（受约束槽位填充）**：在角色先验约束下只处理主张句/方法段，局部锚定槽位

**关键收益**：最大召回杀手 `binding-not-local`（杀掉 46% gold 边的 gate）的本质是关系抽取强迫模型跨句绑定参与者；claim 抽取只需识别主张句+局部槽位锚定——**病灶在新原语下自动消失**。

成本红利：角色分类是廉价任务，重 LLM 只处理主张句——对比现行的全 chunk 重抽取，成本结构更优。

## 4. 与现有工作的划界（related work，非出发点）

- **ScholOnto/nanopublications/micropublications**（2000-2014）：语义模型已设计对但**从未规模化**（手工标注成本杀死）——本方案是 LLM 抽取时代的重做，且补上它们没有的 Method Record/Context 组合运算/版本账本
- **ORKG**：最接近的在建系统，但 property-bag 模型——无论证层/无版本/无条件作用域/无证据绑定
- **HyperGraphRAG/Hyper-KGGen 等**：超边=黑盒事实+自报标量置信——本方案的记录有结构化认识状态
- **论证挖掘**（Lauscher/Binder 线）：证明结构存在+证明专用小模型泛化性死（Feger 2025）——恰好论证只有 LLM 抽取能救
- **SciREX 4-ary / SciFact / SciVer**：n-ary 与 claim 验证的任务级先例——本方案是它们的表示层统一
- **EvoGraph-R1/HGMEM**：记忆/维护侧——本方案的账本更新策略是语料驱动（非 query 驱动）的补充位

组合创新的举证（审稿预判）：必须可证伪对照——**同抽取预算下 claim-ledger vs relation-hypergraph，在条件限定 QA/矛盾检测上比**（§6 主实验）。

## 5. 对科研智能体的杀手级应用（需求侧实证）

1. **条件对齐的矛盾检测**：PaperQA2 用纯 RAG 做到每篇 2.34 处矛盾/70% 人工验证，但回答不了"矛盾双方适用域是否重叠、哪个覆盖我的场景"——只有 Context 作为可组合对象支持 context-matching
2. **agent 实验规划**：EXP-Bench 最强 agent 完整实验成功率 0.5%——Method Record + Context 图支持"目标场景→候选方法→未绑定参数→最近邻先例"
3. **认识论卫生检索**：agent 引用被 hedge 的转述主张时系统知道它是"他人未证主张（条件 C 下）"——直接治 AI Scientist 幻觉文献模块的病
4. **SOTA/方法状态跟踪**：物化视图天然支持"当前最强方法"查询且知道它在哪个 context 下成立

## 6. 评测设计

**主实验（可证伪对照）**：同抽取预算（同 token/调用数）下：
- 臂 A：claim-ledger 抽取（role-first 两阶段 → 五记录四层）
- 臂 B：现行 relation-hypergraph 抽取（slim+refine，同预算）
- 任务：(i) **条件限定 QA**（"X 在什么条件下成立"——67% 条件性实测直接定义的任务族）(ii) **矛盾检测+条件对齐**（"这两篇矛盾的主张适用域是否重叠"）
- 预期：B 的表示在这些任务上结构性答不了（条件被丢弃），A 能答——表示层收益的直接证明

**外接闸门**（防自说自话）：
- 矛盾检测对照 PaperQA2 的人工验证协议
- 方法记录质量对照 EXP-Bench 式下游（实验规划成功率）
- claim 验证对照 SciVer 式任务

**构造 gold**：用现有 gold 构造管线（机器闸+快审方法论）为五种记录建 50-100 篇规模 gold——这个领域没有现成 benchmark，评测能力本身是贡献位（对标 HyperDocRED 之于 Hyper-KGGen 的自建正当性）。

**结构忠实度指标**（新表示特有）：条件保留率（主张带条件比例 vs 原文 67%）、认识状态保真（假设/实证分类准确率）、数值证据绑定率（对 80% 图表指针的捕获）。

## 7. 风险与诚实声明（按严重度）

1. **claim 跨 section 共指**（同一主张三处出现）——最难、无大规模 gold。缓解：多重实现意味着共指不需要完美（每处实现都是合法锚点，共指失败损失去重不损失覆盖）
2. **Context 规范化 + delta 引用解析**（"same setup as [14] but X"）——最深的坑；做不成则条件层退回属性表。但壁垒同源：没人做的原因是没人有跨论文 Method Record 库
3. **组合创新举证**——ScholOnto+micropub+ORKG 组合的质疑必须靠 §6 主实验赢
4. **评测 gold 自建成本**——50-100 篇五记录 gold 是真工作量，但金丝雀/gold 管线现成
5. **适用域边界**：实测基于 5 篇 DRL 经验竞争型论文（2015-2018）——理论型/综述型论文的结构会不同，表示的领域泛化需在第二阶段验证
6. role-first 抽取的假设（修辞角色先验降低抽取难度）未实测——主实验同时验证它

## 8. 与前期工作的资产衔接

- 保留：kernel/n-ary 存储/两阶段 commit/演化机制（超图=序列化层不变）；gold 构造管线；citation intent 通道（delta 链接的原料）
- 转岗：金丝雀/gold 从"抽取质量闸"转为"记录忠实度闸"；E0/E1 审计检查降级为下游应用章节（账本查询恰好支持它们）
- 退役：15-pattern 词表的"抽取 schema"地位（转为 Claim Record 的谓词词表演化位）；停止线旧含义

## 9. 执行计划（预注册骨架）

- **第 1-2 周**：最小可证伪实验——五记录+四层在 5 篇 DRL 语料实现（超图存储不变），role-first 抽取，跑 §6 主对照（同预算 claim-ledger vs relation-hypergraph，条件限定 QA + 矛盾检测）
- **第 3-4 周**：胜出方向扩展——gold 扩到 20-50 篇、context 组合运算、物化视图/SOTA 查询、agent 消费接口（三个杀手应用的 API）
- **判定点**：主对照赢 → 论文主结果确立；单层赢 → 降维保层（四层里总有可辩护的层）；全输 → 表示假设证伪（诚实负结果，这本身是贡献）
