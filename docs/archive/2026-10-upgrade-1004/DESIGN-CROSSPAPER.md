# 跨论文挖掘与组织层升级设计（DESIGN-CROSSPAPER，2026-10-04）

> 范围：叙事 v8「领域世界状态」的编译层（离线、题目盲）与答题管线对它的消费方式。只写设计，不改代码和数据。
> 本档所有 KB 数字均为 10-04 用只读脚本重新核过的（脚本在 `upgrade-1004/scratch/a1-a8_*.py`）；文献一律给一手 arXiv ID，
> 本轮 WebSearch 额度已耗尽，发现层改用 arXiv export API 关键词检索（`scratch/arxiv_q.py`，结果 `discovery*.txt`），
> 验证层用 arXiv id_list 批量直查 + abs 页精读。未核实的条目明确标注。

---

## 0. 一页结论

1. 现在的「状态层」缺的不是更聪明的 LLM 归纳，而是一副骨架：**哪篇论文提出了哪个方法、哪句话引用的是哪篇论文**。
   没有这副骨架，「族成员」「n_papers」「共识/争议」都只能靠名字字符串和嵌入相似度去猜，消融 Δ≈0 是结构性的。
2. 骨架其实大半已经躺在盘上：136 篇综述全文都在 `base_kb/survey_texts/`，135 篇带参考文献节，共 35,848 条书目；
   记录 quote 里的数字引用标记 `[n]` 有 99.2% 能确定性地对上书目条目（6,028 个标记对上 5,979 个）。
   这是全设计里性价比最高的一步：零 LLM、零额度，就能把 survey_claim / lineage / 比较表从「名字」落到「论文」。
3. 建议的升级顺序：书目解析与引用落地 → 提出者抽取 → 谱系边落地 → 用「综述章节成员」做有成员的族 + field_state 全库化
   → 答题端把族级事实做成带支持集的「状态卡」并让规划从状态图出发 → 共识/争议分层与 as-of 切片。
   通用结果矩阵本轮不做（理由见 §3.6），改做「综述报告的比较表单元格」。
4. 能站住的新颖性要收窄：不是「首个领域状态 / 首个谱系图 / 首个分类树生成」（都被占），而是
   「族级事实带跨论文支持集 + 独立性计数 + 带时间的共识/争议/限定/开放状态」，并且有**确定性金标的领域层直接检验**
   （综述章节引用 → 族成员金标）和同模型同截止的可归因消融。详见 §6。

### 1.2 审稿人会拿来对照的清单

| 审稿人期待 | 为什么是「领域状态」而不是「单篇内容」 | 现状 | 差距等级 |
|---|---|---|---|
| A. 论文—方法归属（谁提出了 X） | 谱系、族成员、「X 族的代表工作」都以它为锚 | 无 | 致命：其余各项都靠它 |
| B. 引用落地（句中 [n] / Author (Year) → 具体论文） | 「综述说 A 改进了 B」要能指到 A、B 两篇论文 | 无（cite_bridge_ledger 只有 23 条，样例里 "Papernot et al. [21]" 被错落到一个叫 "security and privacy" 的条目） | 致命 |
| C. 谱系边两端落到论文、有时间顺序 | 「方法怎么演化」是领域级对象的核心 | 两端是名字 | 高 |
| D. 方法族有**成员**（论文/方法集合），跨综述可对齐 | 族 = 一组论文；没有成员就无法算 n_papers、无法做成员级检验 | 族只有名字；跨综述靠名字余弦合并 | 高 |
| E. 族级性质/局限带支持集，且支持来自**独立**论文 | 「多篇合在一起才成立」要能数出来 | 留出检验里有（n_papers），答题 KB 里没有；没有独立性（同作者、综述转述原文算两次） | 高 |
| F. 共识 / 争议 / 限定 / 开放 分层 | 叙事 v8 自己写的卖点；ScholarStack 原文自认不建模 consensus | 无 | 中高（新颖性主要落在这里） |
| G. 比较 / 结果单元格（A 在 D 上比 B 好，按什么指标、什么设置） | 综述读者最常问的「哪个好」 | 比较是文本片段；结果只有 20 篇 | 中 |
| H. 时间维（as-of：某日之前领域是什么状态） | 「状态会变」才叫世界状态；也是截止公平性的前提 | 只有 taxonomy_node 带 as_of（=综述日期）；事实层无 | 中 |
| I. 层本身的直接检验（不只是下游分数） | LKM v2 原文自认 landscape views 未直接评测；这是我们能领先的证据 | 有（留出综述 18 篇），但金标靠 LLM 判匹配，无确定性成员金标 | 中 |
| J. 答题端对状态的消费有可归因增益 | 否则状态层只能降级为分析章（叙事 v8 §3.2 预注册退路） | Δ≈0 | 高 |

结论：A、B 两项不补，C–F 都只能在名字层面打转。好消息是 A、B 的原料（综述全文书目 + 记录里的引用标记 + 摘要里的
"we propose"）已经在盘上，主要是确定性工程。

## 2. 目标数据模型

原则：每类对象必须有消费者（答题端或检验），没有消费者的不建；每条边都带出处（逐字 quote + 所在论文 + 日期）；
LLM 只在「判断」处出现，标识解析与计数一律确定性。

### 2.1 实体

| 实体 | 主键 | 关键字段 | 来源 |
|---|---|---|---|
| Paper | `pid`：KB 内沿用 `arxiv_xxxx`；KB 外的引用论文为**桩节点** `oa:Wxxx` / `arxiv:xxxx` / `doi:...` | title, year, date(首版), authors(姓氏列表), abstract, in_kb(bool), layer | papers.json；arXiv OAI 快照；OpenAlex |
| Method | `mid`（规范名 + 提出论文消歧，例如 `bert@arxiv:1810.04805`） | names[]（别名/缩写）, proposed_by[pid], first_date, generic(bool) | §3.1 提出者抽取；现有 entity_refs 作别名候选 |
| Dataset / Task / Metric | `did/tid/kid` | names[], introduced_by(pid, 可空) | 只从比较表表头与 result.measure 中抽（本轮最小化，不做全库 NER） |
| Area | `aid` | member pids, 来源（综述/聚类）, 代表综述 | §3.4 分区 |
| Family | `fid` | name, definition, members{pid: [证据]}, methods[mid], sources: {induced, survey:[pid]}, agreement（跨综述成员重合度）, first_seen | §3.4 |
| FieldFact | `xid` | family/area, role ∈ {property, limitation, open_problem, comparison}, text（LLM 归纳句）, support[], status 序列 | field_state + §3.5 |

`generic` 标记：像 "transformer"、"LSTM"、"large language model" 这种被几十条谱系当作端点、又不归某一篇论文的名字
（谱系端点频次前 15 里大半是这类），作为方法节点保留但不强行落到提出论文，避免「所有 uses transformer 都连到 Vaswani」
这种看似精确实则无信息的边。

### 2.2 关系

| 关系 | 形式 | 必需出处 | 备注 |
|---|---|---|---|
| PROPOSES | Paper → Method | 自述句（"we propose X"）或他述句（"Zhang et al. [244] proposed STST"，经 B 落地） | 区分 `self` / `third_party`；一方法可有多个候选提出者，取最早且自述优先 |
| CITES | Paper → Paper | 引用句 quote、标记原文、书目条目原文、解析方式与置信度 | `intent` 只对被消费的引用句打（§3.2c） |
| LINEAGE | Method/Paper → Method/Paper，rel ∈ {extends, improves, replaces, combines, uses, compares} | 断言者（谁说的）+ quote + 断言日期 | 两端解析状态分 `paper`/`method`/`name`；时间一致性检查（被继承者不能晚于继承者） |
| MEMBER_OF | Paper/Method → Family | 成员证据：综述章节内的引用 / 归纳器分配 / 两者都有 | 成员证据类型直接决定族的 `sources` |
| SUPPORTS / CONTRADICTS / QUALIFIES | Record → FieldFact | 记录 quote + LLM 判定 + 条件片段（qualify 必须给出条件原文） | §3.5 |
| REPORTS_RESULT | (reporter Paper) → 单元格 (method, dataset, metric, setting, value) | 表格行原文 + 表头 | reporter 可以是综述（「据综述 X 报告」），与原论文自报区分 |

### 2.3 出处、计数与时间

- 每条支持项：`{pid, quote, record_id, date, asserted_by: self|third_party|survey, author_key}`。
- `n_papers` = 支持项里的不同 pid 数；`n_independent` = 去掉「同一组作者」（姓氏集合 Jaccard ≥ 0.5）和
  「综述转述的正是被转述论文自己」之后的数。共识判定用 `n_independent`，不用 `n_papers`。
- 时间：Paper.date 取 arXiv 首版日期（OAI 快照 `versions[0]`）；边的日期 = 断言论文日期；
  FieldFact 的状态是支持集的**纯函数** `status(fact, as_of=T)`，只用 date ≤ T 的支持项重算，不存多份快照、不重跑 LLM。

### 2.4 存储

`base_kb_v3/state/` 下按表存 JSONL（papers_stub / methods / cites / lineage / families / facts / stances / cells），
整体哈希写入 FREEZE 文件。答题端只读。保持现有 `records.json` 不动，新表通过 `record_id` 回指。

## 3. 各组件的流水线设计

成本口径：本地 Qwen3.8-27B 高并发聚合解码约 500 tok/s（调用方给定）；prefill 速度未实测，下文按「输出 token ÷ 500」
估墙钟，prefill 另计、标为未核实。外部额度：OpenAlex 10k credits/日（标题搜索 10、按 id/DOI 批量 ≤50 条 1）；
arXiv HTML 15.5 s/页；arXiv export ≥3 s/次；S2 无 key 约 1 req/s 且有 IP 级 429 风险（只作兜底）；Crossref 约 1 req/s。

### 3.1 提出者 / 归属抽取（PROPOSES）

输入：非综述论文（hub 21 + bulk 1,105；有摘要 ~1,126 篇）的标题、摘要、已有 method 记录；综述的 method_entry 主张（2,711 条）。

1. **自述提出（每篇一次 LLM，JSON）**：给标题 + 摘要 + 该篇 method 记录，要求输出
   `{introduced: [{name, aliases, quote}], used: [{name, quote}]}`；`quote` 必须是摘要中的逐字子串（确定性校验，不通过即丢）。
   确定性先验做提示和校验：标题 "NAME: ..." 前缀（KB 里 189 篇）、"we propose / we introduce / we present X"、
   X 为大写缩写或驼峰（955/2,106 条 method 主语形如命名方法）。"builds upon / based on / uses X" 归入 used（例：
   "Our method builds upon local conformal autoencoders (LOCA)" → used LOCA，不是 proposes）。
2. **他述提出（综述）**：method_entry 与 lineage 中的 "X et al. [n] proposed/introduced Y" 句，经 §3.2 把 [n] 落到论文后，
   生成 `PROPOSES(third_party)`；LLM 只做批量核验（20 句/次，判「这句话是否在说 [n] 提出了 Y」），约 140 次调用。
3. **合并**：同一规范名的多个候选提出者，自述优先、日期最早优先；冲突（两篇都自称提出同名方法，如通用缩写撞名）保留为
   同名不同方法（mid 带提出论文后缀），不强行合并。

成本：自述 1,126 次 × ~150 输出 token ≈ 0.17M token ≈ 6 分钟；留出 18 篇综述的 2,124 篇引用论文 ≈ 11 分钟；
若扩到综述书目桩节点（~6k 篇有摘要，见 §3.4），约 1 小时。

### 3.2 参考文献获取与引用串 → 论文解析（CITES）

**(a) 获取**

| 对象 | 来源 | 成本 |
|---|---|---|
| 136 篇综述 | 本地 `survey_texts/*.md` 的 References 节（已有）；作者-年份式 60 篇另抓 arXiv HTML，用 LaTeXML 的 `<cite>` → `#bib.bibN` 锚点做确定性标记对齐 | 60 × 15.5 s ≈ 16 分钟 |
| KB 非综述 1,126 篇 | OpenAlex 按 arXiv DOI 批量取 work（~23 credits）→ referenced_works 元数据批量（1 credit/50，按平均 40 条估 ~900 credits）；预印本缺 referenced_works 的（refgraph 实测 8 篇里只有 3 篇有）走 arXiv HTML `ltx_bibitem` | HTML 约 700 篇 × 15.5 s ≈ 3 小时（夜间、遵守 robots） |
| 留出 18 篇综述的 2,957 篇引用论文 | 同上；只在需要用书目耦合做分区时抓（P2，可选） | HTML 最坏 ~8.6 小时 |

**(b) 句中标记 → 书目条目**（确定性）

- 数字式：解析 `[n]`、`[n, m]`、`[n–m]`（区间展开上限 20）。本地探针：survey_claim 6,028 个标记对上 5,979 个（99.2%）；
  domain_snapshot 2,601/2,573；lineage 1,599/1,590。被记录引用到的不同（综述, n）对共 6,283 个——这是需要解析到论文的全部条目。
- 作者-年份式：优先用 arXiv HTML 的超链接锚点；没有 HTML 时用「姓氏 + 年份（+ a/b 后缀）」在书目里唯一匹配。
  我的粗探针（书目按空行切分）只唯一命中 608/3,541（17%）、歧义 176，属下界，主要损失在书目切分，不在匹配规则。

**(c) 书目条目 → 论文 id**（按顺序，命中即停）

1. 条目里的显式标识：arXiv id 正则、DOI 正则。
2. 本地 arXiv OAI 元数据快照（共享盘 `arxiv-metadata-oai-snapshot.json`，snapshot_fill.py 已在用）建
   「规范化标题 → id」索引，接受条件：标题前 40 字符相等 + 年份 ±1 + 第一作者姓氏出现在条目里。零额度。
3. KB 标题索引（1,262 篇）。注意：只有 218 条书目条目能对上 KB 标题（82 篇综述）——KB 不是引用闭包，
   绝大多数被引论文会成为 KB 外的**桩节点**，这是设计前提而不是缺陷。
4. OpenAlex 批量标题搜索（refgraph.prefetch 的 OR 拼接：6 个标题/次 = 10 credits），只对 6,283 个被消费条目里前 3 步没解析的
   （估计 ~3k）→ ~500 次 ≈ 5k credits，半天额度。
5. Crossref `query.bibliographic`（无 arXiv 的会议/期刊论文），同样的接受条件。
6. 都不中：保留为「名字级桩」（只有书目原文），不进入任何需要论文身份的计数。

条目字段（作者、年份、标题）的切分：先用 refgraph `_bib_title` 启发式；失败的用 LLM 批量切分（30 条/次，6,283 条约 210 次、
~0.25M 输出 token），**切出的标题必须是条目原文子串**（确定性校验）。GROBID 的 processCitation 是标准替代，但本机未部署（未核实），不作依赖。

**(d) 引用意图**：暂缓。我们消费的引用句绝大多数来自综述（描述性引用），谱系边已经自带 extends/improves/... 关系；
对 hub 论文全文里的 citation_context 再打 ACL-ARC 式意图标签收益不明。等 §4 的消费者证明需要时再加
（LLM 意图分类可行性见 2502.14561；「被引论文贡献类型」标注见 2608.20697）。

### 3.3 谱系边落地（LINEAGE → 论文）

输入：2,422 条 lineage（端点名字、关系、quote、断言论文）；§3.1 的 PROPOSES；§3.2 的标记 → 论文映射。

1. **标记—端点对齐**（确定性为主）：在 quote 里定位两个端点名字的字符位置与已解析标记的位置，把每个标记分给
   同一分句内、位置最近的前一个端点（"STST [244] uses Transformer [12]" 的典型结构）。一个端点多个标记、或标记与两端点
   等距时，交给 LLM 做选择题（"[244] 指的是 A 还是 B 的出处"，选项固定，只能输出 A/B/none），预计 ~300 次。
2. **无标记端点 → PROPOSES 索引**：端点名（含别名）在全局 PROPOSES 表里唯一命中、且不是 `generic` 名 → 落到提出论文；
   多个候选 → 留名字级，不猜。
3. **时间一致性**：extends/improves/replaces/combines 要求被继承端日期 ≤ 继承端日期，违反的边打 `temporal_violation`
   标记（不删，作为解析错误的抽检信号）。
4. **去重与多源**：同一 (from, rel, to) 被多篇综述断言 → 合并为一条边，`asserted_by` 列表即「这条谱系被几篇独立综述认可」。

期望产出（预注册门槛，§5.1）：≥35% 的谱系记录至少一端落到论文、≥15% 两端都落到；抽 100 条人工核两端，精度 ≥0.85。
成本：确定性为主 + ~300 次短 LLM 调用（<5 分钟）。

### 3.4 方法族：从原始论文归纳 + 综述章节成员（复用 field_state.py，扩到全库）

**两个独立来源，再对齐**：

- **结构族（survey-section families，确定性）**：1,215 个 taxonomy_node（129 篇综述）各有 `chunk_id/section`。
  一个节点所在章节里出现的引用标记，经 §3.2 落到论文 → 就是这个族的**成员列表**。这是现有状态层最缺的东西（成员列表现在全空），
  而且不需要 LLM。跨综述族合并改用成员重合（成员 Jaccard ≥0.2 或 ≥3 个共同成员）+ 名字相似，取代纯名字余弦（现在跨 ≥2 综述的族仅 56 个）。
- **归纳族（induced families，LLM）**：沿用 `field_state.compile_field_state`（PROPOSE 80 篇一批 → MERGE → FACTS → PROBLEMS），
  但先做**分区**再按区跑——全库 1,262 篇覆盖 136 个子领域且 bulk 是按 arXiv 类别随机抽的，直接扔进一个 PROPOSE 会得到大量单篇族。

**分区算法**（确定性 + 嵌入）：节点 = KB 论文 + 被消费的桩论文；边权 = 书目耦合（共同参考文献数，来自 §3.2a）
+ 同一综述同章节共被引 + 摘要嵌入余弦 kNN（k=10，cos ≥0.6，用现有 qwen3-embedding-8b）。Leiden/Louvain 社区发现，
以 136 篇综述各自的引用集作为种子约束（一篇综述的引用集大部分应落在同一区）。区的大小上限 ~300 篇，超了递归切分。
这与 HiGTL（2410.03761，引文图层次聚类 + LLM 命名）思路同源，我们不把聚类本身当贡献。

**对齐**：归纳族与结构族按成员 Jaccard 匹配；输出族的 `sources ∈ {induced, survey, both}` 与 `agreement`。
答题端优先使用 `both` 和跨 ≥2 综述的族；`induced` 独有的族是「系统自己发现、没有综述写过的分组」，
在留出检验里单独统计它们的命中率（这是唯一能体现「从原始论文编译」而非「转述综述」的部分）。

**输入扩充（可选，P1 后半）**：被 ≥2 篇 KB 论文/综述引用的桩论文（摘要来自 OpenAlex 批量）也跑粗记录抽取，进入分区与族归纳。
这属于题目盲的引文前沿生长（PAPER-DRAFT-METHOD §3.4 已有此设计），必须在评测前冻结哈希。

成本：留出 18 篇综述用已缓存的逐篇记录重跑 v3 组织层，约 15 次调用/篇 ≈ 270 次，<1 小时。全库：区数 ~40–60，
每区 PROPOSE+MERGE+FACTS+PROBLEMS ≈ 15–30 次，总输出 ~1–3M token ≈ 0.5–1.5 小时；若加 ~6k 桩论文粗抽取，再加 ~1–1.5 小时。
一夜可完成。

### 3.5 共识 / 争议 / 限定 / 开放：在族级事实上做立场判定

不做全库主张两两 NLI（平方级，且绝大多数对互不相关）。单位是 FieldFact：

1. **候选**：对每条族级事实，取 (a) 族成员论文的记录，(b) 引用了成员论文的 KB 论文的记录（经 CITES），
   (c) 混合检索 top-30（以事实句为查询），去重后 ≤40 条。
2. **立场判定**（LLM，15 条/次）：每条候选判 supports / contradicts / qualifies / unrelated；判 contradicts 或 qualifies 时
   **必须给出条件原文片段**（cohort、数据集、规模、设置），片段必须是 quote 的子串（确定性校验，不通过降为 unrelated）。
   依据：BioDivergence（2606.11208）显示大量表面矛盾实为情境差异（"locally valid" 的不同 cohort/protocol），
   所以「限定」必须和「矛盾」分开存，否则争议会被高估。
3. **独立性**：§2.3 的 `n_independent`（去同作者组；综述转述按被转述论文计，不重复计）。
4. **状态规则**（确定性、预注册，不调 LLM）：
   - consensus：n_independent(supports) ≥3、其中 ≥1 条为原论文自述或实验陈述（非仅综述转述）、0 条独立 contradicts；
   - contested：独立 supports ≥1 且独立 contradicts ≥1、且两者条件片段不可区分；或综述原文用 debated/controversial/
     conflicting/mixed results 等词明说争议（词表触发 + LLM 确认）；
   - qualified：supports 与 qualifies 并存且条件可区分（输出「在 C1 下成立、在 C2 下不成立」）；
   - single-source：n_independent = 1；
   - open problem：limitation/open_problem 角色、n_independent ≥2、且在 as-of 时间之后没有记录被判为「解决了它」
     （可选：resolved_by 字段已有 15 条，可用作种子）。
5. **成本**：族级事实规模——留出检验每篇综述 ~70 性质 + ~66 局限；全库按 ~50 区 × ~130 ≈ 6.5k 条。
   6.5k × 40 候选 ÷ 15 ≈ 17k 次调用，输出 ~2.6M token ≈ 1.5 小时，prefill ~34M token（未实测，可能是瓶颈）。
   降本：只对 n_papers ≥2 或被答题端实际检索到过的事实做（后者在 dev 上会引入题目依赖，**不采用**；只用前者，题目盲），约减半。

### 3.6 结果矩阵：本轮不做通用版，改做「综述报告的比较单元格」+「族的评测清单」

**判断：通用的跨论文结果矩阵（方法 × 数据集 × 指标）在我们的 KB 上不可行**，理由全部可核：

- 原论文自报结果只来自 20 篇深读论文（hub 1,443 条 + bulk 67 条）；result 的 `dims` 没有 dataset/metric 槽位，
  按 (数据集, 指标) 组不出任何 ≥2 篇的单元格；1,105 篇 bulk 只有摘要，摘要里的数字没有设置信息。
- KB 是按 arXiv 类别抽样的（不是按任务聚集），同一数据集上有多篇论文自报结果的概率本来就低；要做矩阵得为每个任务
  抓几十篇全文表格，这是另一个项目（AxCell 2004.14356、SciREX 2005.00512、LEGOBench 2401.06233、LAG/League 2502.18209
  都是专门做这件事的，且 LEGOBench 一类基准显示 LLM 从论文生成排行榜仍不可靠——具体数字未在本轮核实）。
- 我们的三个目标基准里没有「给出数值排名」的题型：CS2 dev 15 题里问数据集 1 题、指标 3 题、比较 3 题，都问「有哪些/通常用什么」。

**替代（便宜、有消费者）**：

1. **综述报告的比较单元格**：323 张比较表、2,354 行（557 行带数值）。每行已是 `{claims_about=方法, claim, conditions}`，
   经 §3.2 把行里的引用标记落到论文，结合表头切出 (方法, 数据集/任务, 指标, 值, 年份, 报告者=综述)。
   LLM 只做表头 → 槽位映射（每表一次，323 次）。出处写明「据综述 X 报告」，与原论文自报区分。
2. **族的评测清单（inventory）**：每个族的成员论文里被提及的数据集 / 指标 / 任务，计数 = 提及它的不同成员论文数。
   类型判定（是数据集还是指标）只对被 ≥2 个成员提及的实体做，LLM 批量（50 个/次）。
   这直接服务 CS2 的「通常用哪些数据集/指标」题型，而且天然是跨论文对象（「本族 7 篇里 5 篇用 X」）。

### 3.7 时间维：as-of 切片

- 每个支持项、成员、边都带日期（§2.3）。`status(fact, T)`、`members(family, T)`、`lineage(T)` 都是只读过滤 + 重算规则，
  不重跑 LLM。FieldFact 的文本是 LLM 写的，可能概括了 T 之后的支持项：切片时若 T 之前的支持集为空就整条隐藏；
  不为空但变少时保留原句，同时标出 n_papers(T)（文本措辞不重写，属已知近似，写进局限）。
- **截止执行补漏**：`HybridIndex.search` 与 `state_search` 现在都不按日期过滤（只有外检/引文扩展有截止）。
  CS2 不受影响（KB 最晚 2024、截止 2025-05），但 DSB 按目标论文月份截止，需要在 KB 两个通道都接 `cutoff.allowed`，
  并在答题轨迹里记录「被截止过滤掉的 KB 条目数」以便审计。这是公平性修复，与本设计的收益无关，应先做。
- **时间派生对象**（有消费者才建）：族的成员数按年计数 → 「这个族在 2022 后快速增长 / 停滞」；开放问题的
  「首次被提出时间」与「之后是否被处理」。
- **回测检验**：取 T0 = 2023-01，只用 T0 前的支持项算出 open problem 列表，再看 T0 后的 KB 论文是否有记录处理了它们。
  这与 2608.09968（Evidence-Based Scientific Question Discovery: A Framework with Historical Backtesting，系外行星领域）同形，
  我们把它做成领域层检验的一个子项，不作主卖点。

## 4. 答题管线如何消费状态（让消融不再因结构原因为零）

### 4.1 Δ≈0 的结构原因（读码确认）

1. **内容重复**：state_search 展开的是综述 taxonomy_node / challenges / comparison 的 quote，这些 quote 本来就是 KB 记录，
   普通检索也能拿到；field_state 文档实测 842 条状态证据有 841 条与 KB 记录逐字相同。去掉状态通道 ≈ 去掉一个标签。
2. **族只能按名字找**：查询 → 族名嵌入（阈值 0.55）。族没有成员，命中族也带不来任何「这个族里有哪些论文」的新证据。
3. **排在最后**：`_interleave` 的来源轮转顺序是 target → ext → kb → cite → state，每节截 `max_ev=60`，状态条目最晚进入写作上下文。
4. **写作端看不到「跨论文」**：每条证据是一段孤立的 quote，加了 `[property of 'X']` 前缀；写作 prompt 没有任何地方利用
   「这条结论有 5 篇独立论文支持」。
5. **规划不看状态**：probe 只用 kb.search + 外检；计划生成时不知道这个领域有哪些族、哪些争议。

### 4.2 改法与各自对应的指标机制

| 改动 | 做法 | 预期影响的指标与机制 | 不迎合判分器的约束 |
|---|---|---|---|
| S1 状态卡作为一等证据 | 一张卡 = 一条 FieldFact：`text`（族级句）+ `status` + `n_independent` + 支持项（每项是某篇论文的逐字 quote）。写作端引用卡 id；装配时**展开成对每篇支持论文的引用**，每个引用的 snippet 是该论文自己的 quote | CS2 引用召回（CR）：一句话能带多篇真实出处；成分召回（IR）：族级概括句正是「有哪些/通常如何」类题的成分。DSB：nugget 往往是「一类工作 + 若干代表引用」 | 卡的 text 只能写支持项共同支持的内容；装配时只展开**直接支持该句**的支持项（S1 的风险：族级句被逐个 snippet 判为「部分支持」，引用精度 CP 可能降，见 §4.3） |
| S2 从状态图规划 | probe 后把题目映射到 1–3 个区/族（题目嵌入 vs 族定义 + probe 命中论文与族成员的重合）；把「族名、定义、成员数、争议/开放问题标题」作为规划上下文 | IR：节按族/比较轴组织，减少漏掉整类方法；答案精度 AP：节的范围由真实存在的族决定，比 27B 先验猜的子问题更不容易跑题（10-03 失分分析里 61% 的无关段来自计划跑题） | 映射只用题面与 KB，不看 rubric；族列表来自冻结 KB |
| S3 成员展开检索 | 对命中的族，除按查询检索外，再从族成员论文（KB 记录或桩论文摘要）各取 1–2 条最相关证据 | 召回到「查询词对不上但确属该族」的论文：DSB 的 nugget 覆盖依赖引对论文；CS2 IR | 成员来自题目盲编译；每节成员证据设上限，防止灌水 |
| S4 跨论文综合步 | 写作前对每节证据做一次「一致 / 分歧 / 条件」整理：输入 = 本节卡片 + 证据，输出 = 3–6 条带证据 id 的要点（哪些结论多篇一致、哪里有分歧及条件）；写作端按要点组织段落 | IR 中「比较、优缺点、权衡」类成分；AP：分歧有条件说明，不会把限定结论写成普遍结论 | 要点必须逐条带证据 id，装配器校验 id 存在；要点不进最终文本，只作提纲 |
| S5 截止切片 | 答题时 `status(fact, cutoff)`、`members(family, cutoff)` | 公平性（DSB），不追求提分 | 同上 §3.7 |

### 4.3 风险与对策

- **CP 风险**（S1）：族级句「X 族方法普遍依赖大规模标注」由 5 个 snippet 各自只说了自己一篇，判分器可能判每个引用
  「只部分支持」。对策：装配时只展开那些自身 quote 就蕴含该句核心谓词的支持项（用同一个 27B 做逐项蕴含检查，
  不用判分模型）；另设变体 S1-b「卡只用于规划和选证据，不作为可引用单元」，与 S1 对照。
- **覆盖风险**：KB 只有 1,262 篇，CS2/DSB 题目落在 KB 已有族里的比例可能很低。消融前先测「状态覆盖率」
  （题目 probe 命中族的相似度 ≥τ 的题目比例），按覆盖分层报告：覆盖内的题看组织层效果，覆盖外的题 Δ≈0 是预期，不算失败。
- **长度混淆**：卡片会让写作变长。所有 S 系消融在 ~1,000 词预算下做（与冻结配置一致），并报告长度。

## 5. 评测计划（全部在跑之前写进 PREREG 文件）

### 5.1 硬约束（不满足就不报数）

- **留出隔离**：20 篇留出综述及其 2,360 条记录从所有编译输入中剔除（分区、族归纳、立场判定）；留出检验只给引用论文。
- **题目盲 + 冻结**：编译输入不含任何 benchmark 题面/金标；编译完写哈希进 FREEZE 文件，答题端只读。
- **截止**：KB 两个通道接 `cutoff.allowed`；每题轨迹记录被截止过滤的 KB 条目数；抽 10 题人工核无超截止引用。
- **判分模型与生成模型分离**：生成 Qwen3.8-27B，判分 DeepSeek-V4.1-Flash（与现有协议一致）。

### 5.2 组件内在检验（intrinsic）

| 编号 | 对象 | 样本与方法 | 预注册通过线 |
|---|---|---|---|
| E1 | 标记 → 论文解析 | 分层抽 200 个（数字式 100 / 作者-年份式 100），人工对照综述书目与论文页 | 精度 ≥0.95；被消费标记解析到论文 id 的覆盖：数字式 ≥85%、作者-年份式 ≥60% |
| E2 | PROPOSES | 随机 100 篇非综述论文，人工标「本文提出了什么」 | 精度 ≥0.90、召回 ≥0.75 |
| E3 | 谱系落地 | 抽 100 条已落地边，人工核两端 | 精度 ≥0.85；时间违例 ≤5% |
| E4 | 族成员（确定性金标） | 留出 18 篇：金标 = 综述每个 taxonomy 节所在章节引用的论文（经 §3.2 对到 S2 引用表）；系统族划分 vs 金标划分，算 pairwise F1 与 ARI（只在两边都出现的论文上） | v3 − direct ≥ +0.05 且 CI 下界 >0；v3 优于两个非 LLM 基线（嵌入 k-means 取同 K、书目耦合 Louvain） |

| E7 | 立场判定 | 150 个（事实, 记录）对，人工标 supports/contradicts/qualifies/unrelated | macro-F1 ≥0.70；contradicts 精度 ≥0.70（矛盾少见、误报代价高） |
| E8 | 状态 | consensus 抽 50 条、contested 全部（预计 <50） | 人工认可「可以写成领域共识 / 确有争议」的比例 ≥80% |
| E9 | 时间回测 | T0=2023-01 的 open problem 列表 vs T0 后 KB 论文 | 报告「后来被处理」的比例与人工核 30 条；不设通过线（描述性） |

人工标注量约 750 条判断。建议做法：由我（模型）先按书面规范标注，用户盲审其中 20%（约 150 条），一致率 <90% 的类别
整类改由用户标。这条需要用户确认（§7.3）。

### 5.3 外在检验（extrinsic，消融）

- **CS2**：开发只用 dev 15 题；所有 S 系消融在 ~1,000 词预算下，配对 bootstrap。n=15 的噪声带约 ±0.035，
  所以主假设落在预期会动的分项上：S-full 相对冻结 v9b 的 IR 与 CR 合计 CI 下界 >0；总分 G 非劣（边际 −0.02）。
  逐项消融：−S1（卡片）、−S2（状态规划）、−S3（成员展开）、−S4（综合步）、S1-b（卡片不可引用）。
  CS2 test：v9b 是已冻结的终测；升级版若要上 test，**只跑一次、且在 dev 结论出来前写好预注册**，作为新臂报告，不替换 v9b。
- **DSB**：48 个唯一题固定切 16 题作开发、32 题留作终测；主指标 nugget 覆盖，S-full − v9b ≥ +0.03 且 CI >0。
- **Multi-108**：在 430 篇闭库上题目盲编译状态（同一流水线），报预注册 F1 与严格 F1 两个口径。
- **覆盖分层**：每个基准先算「状态覆盖率」（题目 probe 命中族相似度 ≥τ，τ 在 dev 上定一次后冻结），按覆盖内/外分别报 Δ。
- **退路**（与叙事 v8 §3.2 一致）：若 CS2 与 DSB 的 S-full 都不过线，但 E4/E5 过线 → 状态层的论证收缩为「领域层直接检验」
  + 分析章，不在主表声称下游增益。

### 6.2 还剩下什么新颖性

不能说的：首个领域状态 / 首个方法谱系图（Intern-Atlas）/ 首个从论文生成分类树并按成员评测（TaxoBench、TaxoAdapt、HiGTL）/
首个从文献抽共识（2606.07570）/ 首个区分情境差异与矛盾（BioDivergence）。

可以说、但要靠实验撑住的（按强弱排）：

1. **族级事实带跨论文支持集与独立性计数，并按预注册规则给出带时间的 consensus / contested / qualified / single-source / open 状态**，
   状态是支持集的纯函数，可按任意截止日期重算。竞品里 LKM 有矛盾组无分层、ScholarStack 自认不建模共识、2606.07570 是单领域刻画分析。
   这条成立的前提是 E7/E8 过线。
2. **领域层对综述作者判断的直接检验**：族成员沿用 TaxoBench 的 ARI/V-Measure（不自称新协议），我们多出的是族级性质、
   族级局限、开放问题三类判断的召回，加记忆对照（只给标题）与平面对照（不组织）。LKM / ScholarStack 都没有直接检验。
3. **同模型、同截止下状态层对外部基准的可归因增益**：取决于 §5.3 是否过线；不过线就按退路删掉这条。

结论：叙事 v8「组件都有先例，卖点是两件证据」的判断成立，本设计把第一件证据从「有族和族级事实」加强为「有成员、有支持集、
有状态」，把第二件从「LLM 判匹配」加强为「确定性成员指标 + 人工校准的判分」。

## 7. 分优先级的实施计划

工作量按「一个人 + 本地 27B」估，含实现、跑、抽检；不含等外部额度的墙钟。

### 7.1 P0：骨架（先做，做完才有后面的一切）

| 步 | 内容 | 产出 | 工作量 | 主要风险 |
|---|---|---|---|---|
| P0-0 | KB 两个检索通道接截止过滤 + 轨迹审计字段 | answer_pipeline 小改 | 0.5 天 | 无（公平性修复，独立于本设计） |
| P0-1 | 综述书目解析 + 句中标记 → 条目（数字式确定性；作者-年份式抓 60 篇 arXiv HTML 用 cite 锚点） | `state/bib_entries.jsonl`、`state/markers.jsonl` | 1.5 天 | 作者-年份式切分质量；HTML 没有 LaTeXML 版本的综述只能走姓氏+年份 |
| P0-2 | 条目 → 论文 id（显式 id → OAI 快照标题索引 → KB → OpenAlex 批量 → Crossref） | `state/cites.jsonl`、`state/papers_stub.jsonl` | 1.5 天 | OAI 快照 3.9 GB 在共享盘，建索引一次需流式读完（未测时长）；OpenAlex 与在跑的答题任务共享日额度 |

### 7.4 需要用户拍板的事

1. **不做通用结果矩阵**，改做「综述报告的比较单元格 + 族评测清单」（§3.6）。同意吗？
2. **桩论文进入状态层**：被 ≥2 篇 KB 论文/综述引用的 KB 外论文（用 OpenAlex 摘要）参与分区、成为族成员、可被引用。
   这会改变 KB 构成（需在论文里披露），但它是题目盲的引文前沿生长，和 PAPER-DRAFT-METHOD §3.4 一致。
3. **CS2 test**：v9b 是已冻结终测。升级版若要上 test，按 §5.3 作为新臂只跑一次、预注册在先——还是 test 只保留 v9b、
   升级版只在 dev + DSB 留出 32 题 + 留出综述上报？
4. **人工标注**：约 750 条判断。方案是我先按书面规范标、你盲审 20%（~150 条，估 2–3 小时）；你倾向这样，还是关键两项（E1、E6）由你亲自标？
5. **改两处已写的文字**：PAPER-DRAFT-EXPERIMENTS §6.5「Each survey is removed from the knowledge base」（不准确，20 篇都在答题 KB）；
   NARRATIVE-V8 表里 TaxoBench「只评标签树」（不准确，它用 ARI/V-Measure 评叶节点分配）。
