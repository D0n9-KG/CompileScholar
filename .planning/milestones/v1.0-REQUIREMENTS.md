## v1 Requirements

v1 was intentionally scoped as a trainable scientific-reasoning compiler pilot.

### Route Packet And Replay Input

- [x] **PKT-01**: Build and freeze one real `RoutePacket` around a `topic_scope + cutoff_year`, including inclusion / exclusion reasons, role coverage, trace refs, leakage policy, and `L1` snapshot refs.
- [x] **PKT-02**: Expose packet quality signals before replay compilation, including role coverage, trace completeness, topic boundary quality, and leakage risk.

### Historical Environment Bridge

- [x] **L1-01**: Produce a minimum viable historical environment snapshot for at least one pilot topic, covering resources, benchmarks, toolchains, and protocols.
- [x] **L1-02**: Allow `RoutePacket` and `RouteState` compilation to consume that `L1` snapshot without introducing post-cutoff leakage.

### L3 Replay Compilation

- [x] **L3-01**: Compile `RouteState` from multiple papers plus bounded packet evidence rather than rewriting a single-paper seed.
- [x] **L3-02**: Produce stable `RouteState` outputs covering methods, benchmarks, bottlenecks, enabling conditions, alternative routes, evidence bundles, and uncertainty points.
- [x] **L3-03**: Produce `WhyNowCase` and `RouteComparisonCase` from `RouteState` while preserving explicit evidence chains and uncertainty.

### L2 Surgical Quality Loop

- [x] **L2-01**: Use replay evaluation to identify which `L2` gaps cause route-state, why-now, or prior failures and convert them into actionable repair work.
- [x] **L2-02**: Ensure replay-bound `PaperLogicTrace` artifacts preserve methods, metrics, resources, conditions, limitations, future work, and provenance.

### L4 Decision Layer

- [x] **L4-01**: Derive `DecisionPriorCard` and `AntiPatternCard` from multiple `RouteState` artifacts, with explicit support, counterexamples, held-out consistency, and review state.
- [x] **L4-02**: Assemble `DecisionEpisode` so `L1/L2/L3/L4` objects can live in the same trainable, evaluable, and auditable sample while hindsight stays on the label/eval side.

### Evaluation

- [x] **EVAL-01**: Run a real historical replay on at least one real route packet and produce structured outputs rather than free-text summaries.
- [x] **EVAL-02**: Emit stage-level quality tiers, blockers, failure records, and next-step guidance from replay evaluation.

## v2 Requirement Snapshot

These were not part of shipped v1.0, but they remain the most likely follow-on directions.

### Question Discovery And Hypothesis Work

- **GEN-01**: Generate constrained scientific question candidates from stable `DecisionEpisode` artifacts with preserved novelty / feasibility evidence.
- **GEN-02**: Explore constrained hypothesis generation only after priors and anti-patterns are stable enough to keep the search auditable.

### Productization

- **OPS-01**: Provide operational UI and workflow support for route-packet management, replay runs, failure diagnosis, and human review.
- **CORP-01**: Run batch replay across multiple topics / cutoffs and compare translation quality across domains.

## Out Of Scope For v1.0

| Feature | Reason |
|---------|--------|
| Open-ended autonomous scientific ideation | High-level decision artifacts were not yet stable enough to justify it. |
| A wholesale `L2` rewrite | Replay-driven evidence was a better steering mechanism than broad refactoring. |
| Full-corpus packet discovery before canonical packet / replay contracts existed | Scaling too early would amplify noise and audit ambiguity. |
| Treating `L3/L4` as single-paper abstractions | That would collapse the intended multi-paper historical reasoning boundary. |
