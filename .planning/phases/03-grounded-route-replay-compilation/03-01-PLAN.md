# Plan 03-01: Build Reusable Route-State Packaging

## Objective

把 `support / alternative / held_out` route states 的准备流程从“手工文件列表”提升为一个标准化 package workflow。

## Must Be True

- 多个 route-state entry 可以通过 manifest 批量编译
- 每个 entry 都能追溯到 `packet + traces + optional L1 snapshot`
- replay 可以直接加载 package 产物，而不是要求人工逐个传文件
- grouped outputs 至少覆盖 `support_route_states`、`alternative_route_states`、`held_out_route_states`

## First Cut

第一轮不追求自动发现 route family，只追求：

- contract 清晰
- 输出稳定
- 能服务真实 jamming pilot

## Verification Target

- package CLI 的 fixture 测试通过
- replay 能成功消费 package 产物
- 新输出不会破坏现有 `run_replay_pilot.py` 工作流
